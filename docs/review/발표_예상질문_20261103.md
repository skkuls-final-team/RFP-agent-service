# 발표 예상 질문과 답 (2026-11-03)

11-10 발표에서 받을 만한 질문을 모으고, 질문마다 **말할 답 한두 문장**, **근거 숫자**, **조심할 점**을 적었습니다. 숫자는 모두 실제로 잰 값이고, 정답을 누가 정했는지(사람 / 코드 / Claude 초안)를 함께 적었습니다. 자세한 표는 끝의 출처 문서에 있습니다.

## 먼저 외울 숫자

| 숫자 | 뜻 | 정답을 정한 이 |
|---|---|---|
| **요구사항 재현율 100 %, 정확도 97 %** | 시연 RFP(합성 154 kV GIS 입찰서), AI 끔, 정답 65줄 | Claude 초안 (사람 확인 전) |
| **72 % → 100 %** | 같은 문서, 놓친 줄을 보고 코드 규칙 3개를 더한 전후 | Claude 초안 |
| **위험 조건 4개 중 4개** | 같은 문서, 포괄 조항 2·범위 모호 1·값 불일치 1 | Claude 초안 |
| **유형 22줄 중 18줄** | 실제 RFP, Gemini 3.8 Flash (3.5 Flash-Lite 14줄) | **사람 2명 합의** |
| **6.3분 · 약 600원** | 실제 RFP 한 건(파일 1) AI 켬 처리 시간·추정 비용 | 실행 기록 (단가는 팀 가정) |
| **9초 · 0원** | 시연 RFP, AI 끔 | 실행 기록 |
| **판정 건수 같음** | AI를 끄거나 모델을 바꿔도 판정 5종 건수가 같음 | 코드 |

- 시연에서는 내부 번호("파일 28", "검토 651")를 말하지 않고 문서 이름으로 부릅니다.
- 시연 RFP 정답지는 아직 Claude 초안입니다. 팀이 확인하면(`팀확인사항_20261103.md` 1번) "사람 확인"으로 바꿔 말할 수 있습니다. 그 전에는 "팀이 만든 정답지"라고만 하고 "사람이 검증한"이라고 하지 않습니다.

## 1. 시스템과 역할

### Q1. AI가 판정까지 하나요? 틀리면 누가 책임지나요?
- **답**: "AI는 문장을 읽고 초안을 쓰는 일만 합니다. 숫자 비교와 준수·일탈 판정은 코드가 하고, 확정은 엔지니어가, 최종 승인은 결재자가 합니다. AI를 꺼도 판정은 똑같이 나옵니다."
- **근거**: AI를 끄거나 모델을 3.8 Flash ↔ 3.5 Flash-Lite로 바꿔도 판정 5종 건수가 같았습니다. 시스템 결과는 모두 "후보"이고, 처리 흐름은 담당자 확인·승인 대기에서 실제로 멈춰 사람 동작 없이는 다음으로 가지 않습니다.
- **조심**: "AI가 판정한다"는 표현을 쓰지 않습니다.

### Q2. 그냥 ChatGPT에 RFP를 넣으면 되지 않나요?
- **답**: "수백 쪽을 통째로 넣으면 숫자를 지어내거나 원문 위치를 댈 수 없습니다. 이 시스템은 모든 값에 파일·절·표·행 위치가 붙고, 위치가 없는 값은 화면에 나오지 않습니다. 같은 문서를 넣으면 같은 결과가 나옵니다."
- **근거**: AI가 쓴 문장의 숫자는 자리표시자로 받아 코드가 채우고 원문 값과 대조합니다. 맞지 않는 AI 설명은 버리고 그 수를 실행 기록에 남깁니다("AI 설명 버림 n"). 위험 설명은 두 번째 AI(검증자)가 근거 조각과 한 번 더 대조합니다.

### Q3. 에이전트는 어디에 썼나요?
- **답**: "처리 흐름(LangGraph)이 11단계를 정해진 순서로 돌고, 사람 확인·승인 자리에서 멈췄다가 사람이 누르면 이어 갑니다. 다음에 어디로 갈지는 AI가 아니라 코드 표가 정합니다. AI가 도구를 골라 쓰는 곳은 읽기 전용 검토 도우미 한 곳입니다."
- **근거**: 흐름 상태를 단계마다 DB에 저장해서, 실패한 검토를 다시 시도하면 멈춘 단계부터 이어 갑니다. 엔지니어가 "이 단계부터 다시 처리"를 고를 수도 있습니다. 검토 도우미는 요구사항 찾기·판정 찾기·한 줄 보기 도구만 쓰고, 답에 든 근거 번호와 숫자를 코드가 대조합니다.
- **조심**: "자율 에이전트"라고 하지 않습니다. 결과를 재현할 수 있고 책임이 분명하도록 일부러 고정 흐름으로 만들었다고 말합니다.

### Q4. RAG는 어디에 썼나요?
- **답**: "사람이 고친 유형을 예시로 다시 씁니다. 다른 문서에서 사람이 유형을 고친 줄 중 뜻이 가까운 것을 AI 유형 질문에 '사람이 고른 예'로 넣습니다. 문장 벡터는 지난 확정 힌트와 사전 추가 후보를 찾는 데 쓰고, 결과는 모두 힌트이며 판정 값을 바꾸지 않습니다."
- **근거**: 임베딩은 gemini-embedding-001이고, 사전 표현 186개로 시험해 영어↔한국어 정확도가 84.9 %였습니다(BGE-M3 64.5 %). 기준 유사도는 지난 확정 0.92, 유형 예시 0.80, 사전 후보 0.72입니다.

## 2. 정확도와 테스트

### Q5. 정확도가 얼마나 되나요?
- **답**: "시연 RFP에서 요구사항을 정답 65줄 중 65줄 찾았고(AI 끔), 위험 조건 4개를 모두 찾았습니다. 처음 측정은 72 %였고, 놓친 줄을 하나씩 보고 코드 규칙을 고쳐 올렸습니다."
- **근거 (시연 RFP, 같은 정답지)**

  | | 개선 전 · AI 끔 | 개선 뒤 · AI 끔 | 개선 뒤 · AI 켬 |
  |---|---|---|---|
  | 요구사항 재현율 (K1) | 72.3 % | **100 %** | 93.8 % |
  | 요구사항 정확도 (K2) | 94.0 % | **97.0 %** | 100 % |
  | 값·단위 (K3) | 30/30 | 30/30 | 30/30 |
  | 위험 조건 (K10) | 3/4 | **4/4** | 4/4 |
  | 유형 (K13) | 36/37 | 42/42 | 41/41 |

- **조심**:
  - 정답지는 Claude 초안이고, 시연 RFP는 팀이 만든 문서라 쉬운 조건입니다. "우리 데이터 범위 안에서는 이렇게 동작한다"까지만 말합니다.
  - 실제 RFP 근거로는 **사람 2명이 합의한 유형 22줄(18줄 맞힘)**과 파일 1 사람 확정 판정 17줄 중 15줄(88 %)을 함께 말합니다.

### Q6. AI를 켜면 왜 재현율이 내려가나요?
- **답**: "AI가 입찰자 의무 문장 4줄을 '응답 작성 방법(작성 규칙)'으로 봤습니다. 예를 들어 '제품마다 응답 줄을 하나씩 쓰라'는 문장입니다. 요구사항으로도, 작성 안내로도 볼 수 있는 줄이라 팀이 정답 기준을 정하는 중입니다."
- **근거**: 이 4줄을 작성 규칙으로 보면 AI 켬 재현율이 100 %가 되고, 대신 AI 끔 정확도가 91 %로 내려갑니다(`팀확인사항_20261103.md` 1번).
- **조심**: 숫자를 좋게 보이려고 정답지를 바꾸지 않았다고 말합니다. 비용 협조 요청이 빠지던 줄(8.1 평가 가격 문장)은 코드로 지켜 고쳤습니다.

### Q7. 테스트를 통해 무엇을 고쳤나요? (AI-5)
- **답 (사례 셋)**:
  1. "놓친 줄 18개가 모두 'shall'이 없는 줄이었습니다. 표의 'Mandatory' 칸, 필수 제출물 목록, 위험 표현 문장을 코드 규칙으로 뽑아 재현율을 72 %에서 100 %로 올렸습니다."
  2. "AI가 정한 정답으로 AI 모델을 채점하다가 결론이 뒤집히는 것을 발견했습니다. 그 뒤로 모델 선택은 사람 2명이 확인한 정답으로만 합니다."
  3. "더 싼 모델(3.5 Flash-Lite)로 시간과 비용이 절반이 됐지만 유형 정확도와 문장 초안 검사가 떨어져 되돌렸습니다."
- **근거**: `측정결과_개선기록.md` 개선 기록 표, `개발_기록_C1C2.md`.

### Q8. 테스트는 몇 개나 있나요?
- **답**: "스펙의 시나리오마다 자동 테스트가 하나 이상 있습니다. 백엔드 테스트 약 580개, 화면 테스트(Playwright) 57개 파일이 있고, 요구사항 → 스펙 시나리오 → 화면 → 테스트를 잇는 추적표를 코드가 만들어 CI에서 검사합니다."
- **근거**: 최신 main 전체 pytest 581 통과·30 건너뜀(DB나 원문 파일이 필요한 시험), 화면 테스트 229개 중 223개 통과, 동시 실행 시간 초과 5개는 하나씩 다시 돌려 통과, 1개는 시험의 기대값(문서 종류 규칙 수)이 낡아 고침(11-03). 추적표는 `docs/추적표.md`.

## 3. 비용과 시간

### Q9. 한 건에 비용이 얼마나 드나요?
- **답**: "실제 RFP 한 건(수천 줄)에 약 600원, 시연 RFP는 100~150원입니다. AI를 끄면 0원이고, 판정 결과는 같습니다."
- **근거**: 파일 1 실측 634원(6.3분), 시연 RFP AI 켬 145원(162초)·84원(75초). 분석 밖 AI 사용(검토 도우미 등)도 기능별로 기록해 실행 기록 화면에서 볼 수 있습니다.
- **조심**: 비용은 **팀 가정 단가**(1M 토큰당 입력 $0.50, 출력 $4.00, 1달러 1,500원)로 계산한 추정입니다. 실제 청구서와 대조하기 전에는 "추정"이라고 말합니다(`팀확인사항_20261103.md` 3번).

### Q10. 사람이 하던 일보다 얼마나 빨라지나요?
- **답**: "수백 쪽 RFP의 요구사항 찾기와 제품 비교를 6분 안에 끝내고, 엔지니어는 확인이 필요한 줄과 일탈 후보부터 봅니다."
- **근거**: 처리 시간 6.3분(파일 1, AI 켬), AI 동시 호출로 "15분 넘게"에서 줄임. 판정 값 읽기 17.1초 → 0.87초.
- **조심**: 사람이 손으로 했을 때의 시간은 재지 않았습니다. "몇 배 빨라졌다"는 숫자는 말하지 않습니다.

## 4. 보안과 데이터

### Q11. 고객 RFP가 외부로 나가지 않나요?
- **답**: "밖으로 나가는 곳은 AI 하나뿐이고, 설정 하나로 막습니다. 끄기를 고르면 키가 있어도 아무것도 보내지 않고, 사내 모델 주소로만 보내게 할 수도 있습니다. AI에 보낸 문장과 답의 원문은 저장하지 않고, 호출 수와 토큰 수만 남깁니다."
- **근거**: `RFP_AI_MODE` = gemini / local / off. 지금 방식과 외부 전송 여부가 상태 점검·검토 등록·실행 기록 화면에 보입니다. 고객 원문은 git에 올리지 않습니다.
- **조심**: 시연은 AI 끔(또는 팀 합성 문서만 Gemini로)으로 합니다.

### Q12. 시연 데이터는 실제 RFP인가요?
- **답**: "팀이 만든 합성 입찰서입니다. 실제 RFP에서 볼 수 있는 위험 조항(포괄 조항, 범위 모호, 값 불일치)과 제품을 바꿔 보는 데이터시트 표를 일부러 넣었습니다. 실제 RFP 22건으로는 개발과 측정을 했습니다."
- **근거**: 팀 결정(11-02)으로 합성 RFP로 시연·평가합니다. 실제 RFP의 식별 정보는 발표 자료에 옮기지 않습니다.

### Q13. 제품표 값은 믿을 수 있나요?
- **답**: "LS ELECTRIC 공개 카탈로그와 인증서에서 정리했고, 카탈로그에 없는 값은 '팀 가정'으로 표시합니다. 팀 가정 값으로 한 판정·보증값에는 화면과 산출물에 항상 그 표시가 붙습니다."
- **근거**: 제품표 122행(정격별 행). GIS 정격 전류 등은 카탈로그 쪽수와 함께 채웠습니다.
