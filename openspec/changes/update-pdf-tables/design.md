# 설계: update-pdf-tables

## 결정 (`pipeline/pdf_reader.py`)
1. `_join`: 단락 줄을 공백으로 잇고, 영문자 뒤 "-"로 끝난 줄 다음이 소문자로 시작하면 붙인다. 단락 블록 `text`에 줄바꿈이 없으므로 줄 번호도 단락마다 하나(`line_count` = 1). `source_lines`(판정 상세 원문 앞뒤 줄)는 블록 글을 줄바꿈으로 나누므로 그대로 맞는다.
2. `line_gap`: 쪽 글자 줄 사이 간격(1pt 반올림, 줄 높이 2배 미만만)에서 가장 흔한 값. 그보다 `max(2pt, 0.5배)` 넘게 넓은 간격이 쪽에 있을 때만 그 값을 쓰고, 단락은 간격 > 흔한 값 + max(2pt, 0.5배)일 때 나눈다. 없으면 지금 기준(줄 높이 0.5배). 시제품에서 간격이 고른 쪽(단락 사이를 띄우지 않음)에 흔한 값을 쓰니 문장 다섯이 한 단락이 되어 이 조건을 더했다.
3. `BULLET`: `•·▪◦●○■□※`와 기호 글꼴이 바꾼 `\x80~\x9f`·`~`로 시작하는 줄은 새 단락.
4. `structure.MARK_LEGEND = \bC:\s*(?:\S+\s+){0,4}?Complied`: `document.py`의 공급사 표시 읽기와 문서 종류 규칙 2번 줄 첫 장 표현(`data/seed/doc_kind_rules.csv`, 쉼표가 있어 큰따옴표로 감쌈). docx("C: Complied")도 그대로 걸린다. 요구사항 정답지 만들기(`req_eval.MARK_HEADER`, docx만)는 그대로.
5. `_mark_rows`: 앞 60단락 안에 준수 표시 머리가 있는 PDF만. 머리 뒤 단락 중 `_section_heading`(PART·장·점이 든 번호)이 아니면 표 행 `[표시, 조항]`(새 표 번호, 행 번호 차례). `^[CDE]$` 단락은 다음 단락(절 제목이 아니면)과 합쳐 그 표시가 되고 줄 수를 더한다. `^[CDE]\s+…`로 시작하면 앞 글자가 표시. 행은 `build_tables(supplier_marks=True)`가 표시를 읽어 `MARK_TABLE_ROWS`가 조항을 후보로 뽑는다.

## 측정 (docx 대비 PDF 요구사항 재현율, 규칙만, 공백 무시 글자 맞추기)
| 문서 | 전 | 후 | 주로 고친 것 |
|---|---|---|---|
| f13 미국 사양서(표 없음) | 92 % | 96 % | 접힌 줄 잇기 |
| f06 154 kV GIS 사양 | 81 % | 97 % | 접힌 줄 잇기 |
| f03 115 kV 구매 요청서 | 72 % | 78 % | 단락 간격 |
| f19 한국어 설계기준 | 66 % | 88 % | 단락 간격 |
| f18 공급사 답안(C/D/E) | 26 % | 78 % | 표시 머리·답안 표 행 |
- 측정 파일은 저장소 밖(고객 원문). 시험은 같은 모양의 합성 PDF(reportlab)로 한다.

## 위험
- 간격이 고르면서 줄 간격이 넓은 쪽은 여전히 줄마다 단락이 된다(지금과 같음).
- 준수 표시 머리가 있는 PDF는 절 제목이 아닌 단락이 모두 표 행이 된다. 답안 문서 밖에는 걸리지 않는다.
