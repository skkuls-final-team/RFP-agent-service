# review-workspace Specification

## Purpose
엔지니어가 위험 조건과 내세울 강점을 원문 위치와 함께 먼저 보고 판단만 하도록, 검토 결과를 한국어 요약 + 원문으로 보여 주는 화면이다 (NFR-08).

## Requirements

### Requirement: 문서 올리기와 실행 상태
화면은 docx를 올려 검토를 시작하고, 실행의 현재 단계와 실패 메시지("처리 실패 — 다시 시도")를 보여 줘야 한다(SHALL).

#### Scenario: 처리 중
- **WHEN** 엔지니어가 파일 1을 올리면
- **THEN** 실행이 시작되고 현재 단계가 보인다

### Requirement: 근거와 함께 보이는 결과
화면은 요구사항(유형 칸 포함), 위험 조건, 적합성 판정, 보증값 후보, 일탈·질의 목록, 제안 포인트를 보여 주고, 각 줄에서 원문 위치와 원문을 볼 수 있어야 한다(SHALL). 팀 가정 값이 들어간 줄에는 "팀 가정"이 보여야 한다(SHALL).

#### Scenario: 적합성 표의 비교 제품
- **WHEN** 엔지니어가 적합성 표를 열면
- **THEN** 각 판정의 비교 제품, 제품값, 여유와 방향이 보이고 비교 제품을 바꿔 볼 수 있다

#### Scenario: 손실 환산 결과
- **WHEN** 엔지니어가 손실 환산 결과를 열면
- **THEN** 계산식, 합계, "팀 가정" 표시가 보인다

### Requirement: 판단 동작
화면은 각 후보에 확정·수정·반려(제안 포인트는 채택·버림·수정)를 사유와 함께 남기게 하고, 결재 상신 창에서 지금 걸리는 승인 기준을 미리 보여 주며 결재자와 상신 의견을 받아야 한다(SHALL). 승인자에게는 상신 의견, 걸린 승인 기준과 누락 점검 결과를 보여 주고, 엔지니어에게는 결정 전 상신 취소 버튼을 보여 줘야 한다(SHALL).

#### Scenario: 승인 화면
- **WHEN** 승인자가 승인 대기 실행을 열면
- **THEN** 상신 의견, 걸린 승인 기준, 일탈 후보 수, 목록에 들어간 수, 빠진 일탈이 보인다

#### Scenario: 결재 상신 창
- **WHEN** 엔지니어가 일탈 후보가 있는 검토에서 결재 상신 창을 열면
- **THEN** 지금 걸리는 기준 AR-01이 보이고, 결재자와 상신 의견을 넣기 전에는 상신 버튼이 눌리지 않는다

### Requirement: 내 할 일 화면
화면은 고른 사용자 역할의 "내 할 일"을 보여 줘야 한다(SHALL). 견적·품질·영업 담당은 전달받은 할 일(유형 또는 제안 포인트 종류, 반복 표시, 원문 위치, 상태)을 읽기만 하고 상태 단추는 없다. 기술 검토 엔지니어는 담당자 확인 중인 검토, 승인자는 자기에게 상신된 승인 대기 검토를 걸린 승인 기준과 함께 본다(SHALL).

#### Scenario: 견적 담당 내 할 일
- **WHEN** 견적 담당 사용자를 고르고 "내 할 일"을 열면
- **THEN** 손실 환산 조항 할 일이 원문 위치, 상태와 함께 보이고 상태 단추는 없다

#### Scenario: 엔지니어·승인자의 내 할 일
- **WHEN** 엔지니어가 "내 할 일"을 열면 담당자 확인 중인 검토가, 승인자가 열면 자기에게 상신된 승인 대기 검토가 보이고
- **THEN** 카드마다 걸린 승인 기준이 보이고 누르면 그 검토가 열린다

#### Scenario: 다른 결재자에게 간 검토
- **WHEN** 승인자 두 명 중 한 명에게만 상신된 검토가 있을 때 다른 승인자가 "내 할 일"을 열면
- **THEN** 그 검토는 보이지 않는다

### Requirement: 앱 틀과 화면 주소
화면은 목업과 같은 왼쪽 메뉴(홈, RFP 관리, 지식 관리, 팀 공유, 설정)와 머리글(메뉴 접기, 현재 위치, 검색, 알림, 사용자)을 모든 화면에 보여 줘야 한다(SHALL). 화면마다 주소가 있어 주소로 바로 열거나 새로 고쳐도 같은 화면과 메뉴 강조가 보여야 한다(SHALL). 메뉴 접기 상태는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 메뉴로 화면 이동
- **WHEN** 엔지니어가 RFP 검토 화면에서 지식 관리 > 제품 관리를 누르면
- **THEN** 주소가 제품 관리 화면 주소로 바뀌고 제품 관리 메뉴가 강조되며 현재 위치에 홈과 제품 관리가 보인다

#### Scenario: 메뉴 접기
- **WHEN** 사용자가 메뉴 접기를 누르고 화면을 새로 고치면
- **THEN** 메뉴는 아이콘만 남은 접힌 상태로 보인다

### Requirement: 머리글 사용자 고르기
로그인이 없으므로 화면은 머리글 사용자 칩에서 사용자를 바꾸게 하고, 고른 사용자의 이름과 역할을 머리글에 보여 주며, 모든 화면의 권한을 그 역할로 정해야 한다(SHALL). 고른 사용자는 브라우저에 기억해야 한다(SHALL).

#### Scenario: 사용자 바꾸기
- **WHEN** 엔지니어로 보던 사용자가 사용자 칩에서 기본 승인자를 고르면
- **THEN** 머리글에 기본 승인자와 승인자 역할이 보이고 새로 고쳐도 유지된다

### Requirement: 예시로 보이는 알림
알림 API가 없는 동안 화면은 머리글 알림을 예시 데이터로 보여 주고 "예시" 표시를 붙여야 한다(SHALL). 예시 알림은 저장하지 않는다.

#### Scenario: 알림은 예시로 보인다
- **WHEN** 사용자가 머리글 알림 단추를 누르면
- **THEN** "예시" 표시가 붙은 알림 목록이 보이고 모두 읽음으로 하면 읽지 않은 수가 0이 된다

### Requirement: 검토 정보 입력과 표시
화면은 검토를 시작할 때 검토 정보(사업명, 검토명, 고객사, 국가, 제출 마감일, 담당 엔지니어)를 넣을 칸을 보여 주고, 검토 목록과 검토 머리글에 검토 번호·검토 정보·마감까지 남은 날(D-day)을 보여 줘야 한다(SHALL). 검토명이 비어 있으면 첫 파일 이름을 대신 보여 준다. 머리글에서 검토 정보를 고칠 수 있어야 한다(SHALL).

#### Scenario: 목록에서 마감 보기
- **WHEN** 마감일이 3일 뒤인 검토가 있는 상태에서 검토 목록을 열면
- **THEN** 그 줄에 검토 번호, 사업명, 검토명, 고객사, 담당 엔지니어, "D-3"과 요구사항·위험·일탈·제안 개수가 보인다

#### Scenario: 검토명이 빈 검토
- **WHEN** 마감일만 넣고 시작한 검토를 목록에서 보면
- **THEN** 검토명 자리에 첫 파일 이름이 보이고 마감 자리에 D-day가 보인다

#### Scenario: 머리글에서 고치기
- **WHEN** 엔지니어가 검토 머리글에서 고객사를 고치고 저장하면
- **THEN** 머리글과 목록에 새 고객사가 보이고 이력 탭에 그 변경이 보인다

### Requirement: 검토 상세 요약 칸과 탭
화면은 처리를 마친 검토 상세의 제목 줄 아래에 정보 3묶음과 탭 줄을 목업 v4.96 순서대로 보여야 한다(SHALL). "검토"는 제출 마감·D-day, 상신 권장일(마감 2일 전), 문서 수·묶음·규격 체계, 담당·결재자, "사업"은 사업명·고객사·국가·고객 입찰 번호·영업, "판정 진행"은 꼭 볼 것(일탈·질의·확인 필요 합과 각 수), 준수 수, 작성할 칸(빈칸·전체), 손실 환산(조항이 있을 때)이다. 탭은 판정·위험 조건·문서 읽기 점검·상업 조건·이력과 "더 보기"(손실 환산 (참고)·입찰 영향·지난 RFP 비교·제출본)이고, 판정 탭 옆에 꼭 볼 것 수를 보인다. 예시 띠는 없다. 확인 필요 비율과 뺀 직접 작성할 칸 수는 결재 상신 창에만 보인다. [결정]

#### Scenario: 요약 칸
- **WHEN** 일탈 후보가 있는 검토 상세를 열면
- **THEN** 정보 묶음 검토·사업·판정 진행이 보이고, 판정 진행에 꼭 볼 것·준수·작성할 칸이 보이며 예전 요약 칸(확인 필요 비율 칸)은 없다

#### Scenario: 꼭 볼 것
- **WHEN** 일탈 후보 2·질의 후보 2·확인 필요 8·준수 45줄인 검토 상세를 열면
- **THEN** 판정 진행에 "꼭 볼 것 12줄"과 "일탈 2 · 질의 2 · 확인 8", "준수 45줄"이 보이고 판정 탭 이름 옆 수가 12다

#### Scenario: 사업 묶음
- **WHEN** 사업이 연결된 검토 상세를 열면
- **THEN** 사업 묶음에 고객 입찰 번호와 영업 담당 이름이 보인다

#### Scenario: 상신 권장일
- **WHEN** 제출 마감이 6일 남은 검토 상세를 열면
- **THEN** 검토 묶음의 상신 권장에 마감 2일 전 날짜가 보인다

#### Scenario: 더 보기 탭
- **WHEN** "더 보기"에서 손실 환산 (참고)를 고르면
- **THEN** 손실 환산 탭 내용이 보이고 탭 줄 끝에 "손실 환산 (참고)"가 선택된 것으로 붙는다

#### Scenario: 직접 작성할 칸 표시
- **WHEN** 직접 작성할 칸이 3개인 검토에서 결재 상신 창을 열면
- **THEN** 확인 비율 줄에 "직접 작성할 칸 3개는 뺌"이 보인다

#### Scenario: 탭으로 내용 바꾸기
- **WHEN** 검토 상세에서 "이력" 탭을 누르면
- **THEN** 이력 표가 보이고 탭 줄에서 이력 탭이 선택된 것으로 보인다

#### Scenario: 예시 탭
- **WHEN** 마지막 예시 탭이던 "지난 RFP 비교" 탭을 열면
- **THEN** 예시 띠가 보이지 않는다

### Requirement: 판정 표 거르기
화면은 판정 탭에 판정 칩(전체와 판정 값마다, 건수), "확정 안 한 줄만", 검색어, 유형 거르기를 두고 판정 순서로 정렬한 판정 표(판정, 항목 이름·영문, 요구값, 제품값·보증값, 원문 위치)를 페이지로 나눠 보여야 한다(SHALL). 표 아래에 보이는 줄 수와 전체 판정 수를 보인다(SHALL).

#### Scenario: 판정 칩으로 거르기
- **WHEN** 판정 탭에서 "일탈 후보" 칩을 누르면
- **THEN** 표에는 일탈 후보 줄만 보이고 칩의 건수와 표 아래 줄 수가 같다

#### Scenario: 거른 결과가 없음
- **WHEN** 맞는 줄이 없는 검색어를 넣으면
- **THEN** "조건에 맞는 판정이 없습니다"와 필터 지우기가 보인다

### Requirement: 위험 조건 탭
시스템은 위험 조건 탭 머리에 닫지 않은 위험 조건 수를 종류별로 보이고, 위험 조건마다 상태, 종류와 표현 또는 항목 이름·값, 설명, 원문 위치를 한 줄로 보여야 한다(SHALL). 문제 없음으로 닫은 줄은 흐리게 맨 아래에 두고 닫은 사유와 누가·언제 닫았는지 보인다. 엔지니어는 담당자 확인 단계에서 후보를 위험으로 확정하거나, 사유를 적어 문제 없음으로 닫을 수 있다(SHALL).

#### Scenario: 위험 조건 건수
- **WHEN** 포괄 조항·값 불일치·범위 모호 후보가 하나씩 있는 실행의 위험 조건 탭을 열면
- **THEN** 머리에 "포괄 조항 1 · 값 불일치 1 · 범위 모호 1"이 보이고, 줄 3개에 "후보" 배지와 원문 위치가 보인다

#### Scenario: 문제 없음으로 닫기
- **WHEN** 엔지니어가 값 불일치 후보에서 문제 없음을 누르고 사유를 적어 닫으면
- **THEN** 그 줄은 "문제 없음" 배지로 흐리게 맨 아래에 가고, 사유와 닫은 사람이 보이며, 머리의 값 불일치 수가 0이 된다

#### Scenario: 사유 없이 닫기
- **WHEN** 문제 없음 사유 칸이 비어 있으면
- **THEN** 닫기 단추가 눌리지 않는다

#### Scenario: 위험으로 확정
- **WHEN** 엔지니어가 포괄 조항 후보를 위험으로 확정하면
- **THEN** 그 줄의 배지가 "확정"이 되고 확정한 사람이 보인다

### Requirement: 손실 환산 탭
시스템은 손실 환산 탭에 고객 손실 환산 조항이 있을 때만 계산한 참고값이라는 안내, 단가 행 위치, 무부하·부하·보조마다 단가·손실값·가산액, 가산액 합계를 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 손실값을 넣어 다시 계산할 수 있고, 직접 넣은 값이 들어간 결과에는 "팀 가정"을 보인다(SHALL). 조항이 없으면 계산하지 않았다고 알린다. 단가·단위·비교 제품·손실값·팀 가정이 모두 같은 단가 표는 한 상자로 묶어 원문 위치를 모두 보이고, 묶인 상자에 넣은 손실값은 묶인 표 모두에 저장한다(SHALL).

#### Scenario: 손실 환산 표
- **WHEN** 손실 환산 단가 행이 있고 비교 제품이 없는 실행의 손실 환산 탭을 열면
- **THEN** 무부하·부하·보조 줄에 단가가 보이고, 손실값 칸은 비어 있으며, 가산액 합계는 "—"이다

#### Scenario: 손실값 넣어 다시 계산
- **WHEN** 엔지니어가 세 손실값을 60·300·8 kW로 넣으면
- **THEN** 줄마다 가산액과 합계 $1,240,400이 보이고 "팀 가정" 표시가 붙는다

#### Scenario: 조항 없는 RFP
- **WHEN** 손실 환산 조항이 없는 실행의 손실 환산 탭을 열면
- **THEN** "이 RFP에는 손실 환산 조항이 없어 계산하지 않았습니다."가 보인다

#### Scenario: 같은 조건 손실 환산 표 묶기
- **WHEN** 단가가 같고 비교 제품이 없는 단가 표 세 개가 있는 실행의 손실 환산 탭을 열면
- **THEN** 상자 하나에 "같은 조건 3곳"과 세 원문 위치가 보이고, 손실값을 넣으면 세 표 모두에 저장된다

### Requirement: 입찰 영향 탭
시스템은 입찰 영향 탭에 유리한 점으로 제안 포인트(근거, 상태, 문장, 종류와 원문 위치, 팀 가정·숫자 불일치 표시)를, 불리한 점으로 일탈 후보와 질의 후보 판정(항목 이름 + "미달" 또는 "값 불명확", 대응 문장)을 보여야 한다(SHALL). 엔지니어는 담당자 확인 단계에서 제안 포인트를 채택하거나 사유를 적어 버릴 수 있다(SHALL). 채택·버림은 단추로 보이고, 누르면 그 포인트에 결과 알림(채택은 전달받는 담당, 버림은 사유)을 보이며, 채택한 줄과 버린 줄을 색으로 구분해야 한다(SHALL). [제안] 불리한 점이 없으면 "불리한 점이 없습니다."를 보인다.

[제안]

- **WHEN** 엔지니어가 다른 비교 제품을 눌러 다시 판정이 끝나기 전이면

시스템은 이력 탭에 수정 이력을 새것부터 시각, 사람, 무엇을 어떻게 바꿨는지 한 줄 문장, 사유(결재·상신은 의견)로 보이고, 맨 아래에 시스템이 판정을 만든 줄을 보여야 한다(SHALL). 문장은 기록된 값만 쓴다.

#### Scenario: 판정 바꾼 이력

시스템은 검토 상세 머리의 "내보내기"에서 "일탈 목록 초안 (Word)"·"질의서 초안 (Word)"를 고르면 진행 화면을 보인 뒤 Word 파일을 내려받고 "<파일 이름>를 만들었습니다." 알림을 보여야 한다(SHALL). 내보내기에는 TBE 준수표와 데이터시트 채우기도 있어 그 화면을 연다. 일탈·질의 문장은 판정 상세 화면(위험 조건에서 나온 문장은 위험 조건 줄을 펼친 곳)에서 보이고, 엔지니어는 담당자 확인 단계에서 문장을 확정하거나, 사유를 적어 고치거나 목록에서 뺄 수 있다(SHALL).

#### Scenario: 내보내기 묶음

- **THEN** 일탈 목록 초안 (Word) · 질의서 초안 (Word) · TBE 준수표 · 데이터시트 채우기 네 가지가 보인다

#### Scenario: 일탈 목록 초안 내려받기

- **THEN** 진행 화면이 보였다가 "일탈 목록 초안_<검토 번호>.docx" 파일이 내려받아지고 만들었다는 알림이 보인다

#### Scenario: 사유 적어 문장 고치기
- **WHEN** 엔지니어가 판정 상세 화면의 질의 문장을 고치면
- **THEN** 사유 칸이 나오고 사유가 비면 문장 저장 단추가 눌리지 않으며, 사유를 적어 저장하면 고친 문장이 "확정" 상태로 남는다

### Requirement: 문서 읽기 점검 탭
시스템은 문서 읽기 점검 탭에 종류별 건수(표·그림·단위·위치), 확인 안 한 건수 표시, 안내 문장과 점검 표(종류와 무엇, 위치·파일·문제·할 일, 확인 단추)를 보여야 한다(SHALL). 엔지니어가 "직접 확인함"을 누르면 "확인함"과 사람·시각, "되돌리기"가 보이고 줄이 흐려진다. 탭 이름 옆에는 확인 안 한 건수를 보인다. 점검 줄이 하나도 없으면 빈 표 대신 "모든 문서를 끝까지 읽었습니다"와 살핀 것(표 칸 역할·그림·단위·절 번호)을 보이고, 머리 표시는 "읽지 못한 곳 없음"이다. [제안]

#### Scenario: 점검 줄 확인
- **WHEN** 엔지니어가 문서 읽기 점검 탭에서 한 줄의 "직접 확인함"을 누르면
- **THEN** 그 줄에 "확인함"과 엔지니어 이름이 보이고, 머리 표시와 탭 이름 옆 건수가 하나 줄며, 이력 탭에 "문서 읽기 점검 확인" 줄이 생긴다

- **WHEN** 확인한 줄의 "되돌리기"를 누르면
- **THEN** 다시 "직접 확인함" 단추가 보이고 확인 안 한 건수가 늘어난다

#### Scenario: 고칠 수 없을 때 확인 단추
- **WHEN** 엔지니어가 아닌 사용자가 문서 읽기 점검 탭을 열면
- **THEN** "직접 확인함" 단추가 눌리지 않고 이유가 안내된다

#### Scenario: 읽지 못한 곳이 없는 검토
- **WHEN** 읽지 못한 곳이 없는 합성 데이터시트 검토의 문서 읽기 점검 탭을 열면
- **THEN** 점검 표 없이 "모든 문서를 끝까지 읽었습니다"와 "직접 확인할 곳이 없습니다"가 보이고, 머리 표시는 "읽지 못한 곳 없음", 탭 이름 옆에는 숫자가 없다

시스템은 결재 상신 창의 상신 전 확인 목록에 문서 읽기 점검 줄을 넣어야 한다(SHALL). 확인 안 한 점검이 있으면 "문서 읽기 점검 미확인 n건"(주의), 없으면 "문서 읽기 점검 모두 확인"을 보인다. 미확인이 남아도 상신할 수 있다.

- **THEN** 상신 전 확인에 "문서 읽기 점검 미확인 n건"이 주의 표시로 보인다

### Requirement: 제출본 탭
시스템은 제출본 탭에 승인된 실행의 제출본을 버전(v1), 확정 시각(승인 시각), 결재자, 판정 줄 수, 일탈·질의 후보 수, 첨부, 상태("현재 제출본")로 보여야 한다(SHALL). 승인된 실행에는 "인계 패키지 내려받기"와 엔지니어용 "영업에 넘기기"를 두고, 마지막으로 넘긴 시각·받는 주소 또는 "주소 없음"·"발송 실패"를 보인다(`add-submission-package`). 승인 전이면 제출본이 없다는 안내를 보인다. 승인된 실행은 판정을 고칠 수 없으므로 승인 시점의 판정이 제출본이다. 머리 단추는 승인된 실행에서 "제출본 v1 확정"으로 보인다.

#### Scenario: 승인된 실행의 제출본
- **WHEN** 승인자가 승인한 실행의 제출본 탭을 열면
- **THEN** v1 줄에 결재자 이름, 판정 줄 수, 일탈·질의 후보 수와 "현재 제출본"이 보이고, 머리 단추는 "제출본 v1 확정"이다

- **THEN** "아직 확정된 제출본이 없습니다"로 시작하는 안내가 보인다

- **THEN** "영업 담당(주소)에게 인계 패키지를 보냈습니다" 알림이 보이고 탭에 넘긴 시각이 보인다

### Requirement: 처리 상태 화면
시스템은 처리 중인 검토 상세에 로고, 진행 막대와 백분율, 지금 단계 문장(찾은 문서·요구사항 수 포함)을 보여야 한다(SHALL). 문서 읽기 단계는 세부 일과 AI 일의 처리 줄 수(예: "AI로 유형 붙이는 중 480 / 3,397줄")를 함께 보이고, 백분율은 단계 순서와 세부 진행으로 센다(문서 읽기 단계가 막대 대부분). 지난 시간과 예상 시간 안내를 보이고, 마지막 진행이 10분 넘게 없으면 멈췄을 수 있다고 알린다. "분석 취소" 단추를 누르고 한 번 더 확인하면 취소를 요청하고, 처리가 멈추면 분석 실패 화면으로 바뀐다. 처리가 끝나면 다시 묻지 않아도 검토 상세(탭과 요약 칸)로 바뀐다. [제안]

#### Scenario: 처리 중인 검토
- **WHEN** 위험 조건 찾기 단계를 처리하는 중인 검토 상세를 열면
- **THEN** 진행 막대의 값이 0보다 크고 100보다 작으며 "위험 조건 찾는 중"이 보이고, 처리가 끝나면 판정 탭이 보인다

#### Scenario: 유형 붙이기 진행
- **WHEN** 문서 읽기 단계에서 AI 유형 붙이기 480 / 3,397줄을 처리하는 중인 검토 상세를 열면
- **THEN** "AI로 유형 붙이는 중 480 / 3,397줄"과 지난 시간이 보이고, 진행 막대 값은 같은 단계의 0줄일 때보다 크다

#### Scenario: 오래 진행이 없음
- **WHEN** 마지막 진행 시각이 11분 전인 처리 중 검토 상세를 열면
- **THEN** "10분 넘게 진행이 없습니다" 안내가 보인다

#### Scenario: 처리 중 분석 취소
- **WHEN** 처리 중인 검토 상세에서 "분석 취소"를 누르고 확인 단추를 누르면
- **THEN** 취소 요청이 가고 "취소하는 중" 안내가 보이며, 처리가 멈추면 분석 실패 화면에 "취소했습니다"가 보인다

### Requirement: 분석 실패 화면
시스템은 처리에 실패한 검토 상세에 멈춘 단계와 오류 문장, 다섯 묶음 진행 상황(끝남·멈춤·대기), 지금 볼 수 있는 결과 수, 문서 목록과 읽은 상태, 처리 기록, 복사할 수 있는 문의용 정보를 보여야 한다(SHALL). 다른 실패한 검토가 있으면 그 검토로 가는 연결을 보인다. 계속하는 방법 가운데 "다시 시도"는 검토를 다시 처리하게 하고 처리 상태 화면으로 바꾼다. 나머지 방법은 예시 영역으로 보이고 눌러도 처리하지 않는다. 사람이 취소한 검토는 "○○ 단계에서 취소했습니다"를 보인다.

#### Scenario: 분석 실패 상세
- **WHEN** 위험 조건 찾기 단계에서 실패한 검토 상세를 열면
- **THEN** "위험 조건 찾기 단계에서 멈췄습니다"와 오류 문장이 보이고, 진행 상황은 문서 읽기 끝남, 위험 조건 찾기 멈춤, 나머지 대기이며, 문서 목록에 올린 파일 이름이 보인다

#### Scenario: 계속하는 방법 예시
- **WHEN** 실패 화면에서 "남은 부분은 직접 확인"을 고르고 실행 단추를 누르면
- **THEN** 예시 띠가 보이는 영역이고 "예시 화면이라 처리하지 않았습니다" 알림만 보이며 검토 단계는 그대로다

#### Scenario: 실패 화면에서 다시 시도
- **WHEN** 취소한 검토의 실패 화면에서 "다시 시도"를 고른 채 실행 단추를 누르면
- **THEN** 다시 시도 요청이 가고 화면이 처리 상태 또는 검토 상세로 바뀐다

### Requirement: 협조 요청 현황 화면
시스템은 협조 요청 화면에 수신 부서 탭(견적·품질·영업 담당, 미분류), 미발송·회신 대기·24시간 넘게 회신 없음·회신 완료 수, 요청 표(상태, 요구사항과 검토 번호·원문 위치, 보낸 주소, 보낸 일시, 발송 실패 표시)를 보여야 한다(SHALL). 요청 항목은 유형별로 보낸 할 일(FR-11)이다. 발송 실패하거나 판정이 없어 아직 안 보낸 요청에는 "보내기", 회신 대기 요청에는 엔지니어에게 "재요청"이 있다. 줄을 누르면 요청 내용, 원문, 회신 요지, 진행(생성 → 메일 발송 → 회신 완료)을 보이는 창이 열리고, 엔지니어는 그 창에서 회신 요지를 적고 "회신 완료"을 표시한다. [결정] 메일은 시스템이 보내고, 자동 재요청 알림은 없으며, 요청하기는 예시 창이다.

#### Scenario: 수신 부서별 요청 현황
- **WHEN** 엔지니어가 협조 요청 화면에서 품질 담당 탭을 고르면
- **THEN** 형식시험 성적서 요청 줄이 "미발송" 또는 "메일 발송"으로 검토 번호, 파일 이름이 든 원문 위치와 함께 보이고, 요약 줄에 상태별 수가 보인다

#### Scenario: 24시간 넘게 미확인
- **WHEN** 메일을 보낸 지 24시간이 넘도록 회신 완료이 아닌 요청이 있으면
- **THEN** 그 줄의 상태가 "24시간 넘게 회신 없음"이고 상세 창 진행에 "재요청 필요"가 보인다

#### Scenario: 받는 담당자의 확인
- **WHEN** 엔지니어가 메일 발송인 요청의 상세 창에서 회신 요지를 적고 "회신 완료"을 누르면
- **THEN** 그 줄은 "회신 완료"으로 흐려지고, 다시 열면 회신 요지와 진행의 "회신 완료" 단계가 보인다

#### Scenario: 요청하기 예시
- **WHEN** 엔지니어가 "요청하기" 창에 요구사항과 요청 내용을 적고 "요청 보내기"를 누르면
- **THEN** 예시 띠가 보이는 창이고 "예시 화면이라 보내지 않았습니다" 알림만 보이며 요청 항목 수는 그대로다

#### Scenario: 재요청
- **WHEN** 메일을 보낸 지 24시간 넘은 요청의 줄에서 엔지니어가 "재요청"을 누르면
- **THEN** "다시 보냈습니다" 알림이 보이고 보낸 일시가 지금으로, 회신 기한이 3일 뒤로 바뀐다

#### Scenario: 재요청은 엔지니어만
- **WHEN** 품질 담당 사용자가 협조 요청 화면을 열면
- **THEN** "재요청" 단추가 없다

### Requirement: 홈 화면
시스템은 홈에 나의 업무 세 칸(내가 처리할 건, 결재 대기, 3일 내 마감), 오늘 할 일(내 차례인 검토를 상신 권장일 빠른 순 3건, 이유·단추), 나의 검토 일정(일정·단계별·사업별 보기), 어제 이후 바뀐 것을 보여야 한다(SHALL). 엔지니어는 자기가 담당인 검토, 다른 역할은 모든 검토를 본다. 일정은 7일 달력에 제출 마감과 상신 권장을 놓는다. 단계별은 단계 열 카드, 미확인 협조 요청이 남은 담당자 확인 검토는 "협조 대기" 열이다. 실패한 검토 알림의 [재시도]는 엔지니어가 다시 시도를 시작한다. 공지·행사는 예시 영역이다.

#### Scenario: 내 업무와 단계별 카드
- **WHEN** 엔지니어가 오늘 마감이고 품질 담당 협조 요청이 남은 자기 검토가 있는 상태로 홈에서 "단계별"을 고르면
- **THEN** 그 검토 카드가 "협조 대기" 열에 검토 번호, 검토명, D-Day, 협조 미확인 수와 함께 보이고, "3일 내 마감" 칸 수가 0이 아니다

#### Scenario: 내 업무 칸으로 강조
- **WHEN** 홈 단계별 보기에서 "결재 대기" 칸을 누르면
- **THEN** "결재 대기" 필터 칩이 보이고 결재 대기가 아닌 카드는 흐려지며, 칩을 누르면 다시 보통으로 보인다

#### Scenario: 사업별 보기
- **WHEN** 홈에서 "사업별"을 고르면
- **THEN** 카드가 사업 이름 아래로 모이고 카드마다 단계 칩이 보인다

#### Scenario: 분석 실패 알림
- **WHEN** 엔지니어의 검토가 위험 조건 찾기 단계에서 실패한 상태로 홈을 열면
- **THEN** "<검토 번호> <제목> 분석이 멈췄습니다"와 오류 문장, 멈춘 단계가 든 알림과 검토 상세로 가는 "오류 내용 보기"가 보이고, 닫으면 알림이 사라진다

#### Scenario: 홈에서 다시 시도
- **WHEN** 엔지니어가 처리 실패한 자기 검토의 홈 실패 알림에서 [재시도]를 누르면
- **THEN** 그 검토의 다시 시도가 요청되고 "다시 분석을 시작했습니다" 알림이 보인다

#### Scenario: 팀 공유와 행사 예시
- **WHEN** 홈의 팀 공유를 보면
- **THEN** 팀 업무에 사용자마다 하는 일(승인자는 결재, 담당자는 협조 요청)이 보이고, 공지사항 탭과 행사 영역은 예시 띠와 함께 열고 넘길 수 있다

#### Scenario: 오늘 할 일 순서
- **WHEN** 엔지니어에게 담당자 확인 단계 검토 2건(제출 마감 D-3, D-6)이 있는 상태로 홈을 열면
- **THEN** 오늘 할 일 첫 줄은 D-3 검토이고 이유에 "상신 권장"과 확인 필요 줄 수가 보이며, "내가 처리할 건" 수는 내 차례인 검토 수와 같다

#### Scenario: 오늘 할 일 없음
- **WHEN** 내 차례인 검토가 없는 상태로 홈을 열면
- **THEN** 오늘 할 일에 "지금 내 차례인 검토가 없습니다."가 보인다

#### Scenario: 일정 달력
- **WHEN** 제출 마감이 오늘부터 4일 뒤인 담당자 확인 검토가 있는 상태로 홈 일정 보기를 열면
- **THEN** 마감 날 칸에 "제출 마감"이, 2일 전 칸에 "상신 권장"이 그 검토 이름과 함께 보인다

#### Scenario: 어제 이후 바뀐 것
- **WHEN** 어제 분석이 끝난 내 검토 1건이 있는 상태로 홈을 열면
- **THEN** "어제 이후 바뀐 것 1건 · 분석 끝남 1"이 보이고, 펼치면 그 검토 줄과 [가기]가 보인다

### Requirement: 제품표 화면
화면은 제품표를 제품군 탭과 검색으로 보여 주고, 빈 칸과 팀 가정 값을 구분해 표시해야 한다(SHALL). 줄을 누르면 오른쪽 빠른 보기에 핵심 정격(값·출처), 값이 없어 막힌 판정, 지금 쓰이는 검토(결과별 수), 같은 제품군에서 대신 쓸 수 있는 제품(참고)을 보이고, 제품 코드나 [상세 화면]을 누르면 제품 상세 화면으로 간다(SHALL). 두 제품을 골라 비교하고, "내보내기"로 지금 거르기대로 엑셀을 내려받는다(SHALL). 고치기와 엑셀 가져오기는 두지 않는다.

#### Scenario: 제품 상세
- **WHEN** 엔지니어가 제품표에서 판정에 쓰인 제품 줄을 누르면
- **THEN** 오른쪽 빠른 보기에 그 제품의 핵심 정격과 지금 쓰이는 검토가 보이고, 검토를 누르면 그 검토가 열리며 [상세 화면]을 누르면 제품 상세 화면으로 간다

#### Scenario: 대신 쓸 수 있는 제품
- **WHEN** 같은 제품군에 단시간 견딤 전류가 더 높은 제품이 있는 제품의 빠른 보기를 열면
- **THEN** "대신 쓸 수 있는 제품"에 그 제품과 "단시간 50 kA (+10)" 같은 차이가 보인다

#### Scenario: 두 제품 비교
- **WHEN** 엔지니어가 두 제품을 골라 비교를 누르면
- **THEN** 두 제품의 같은 칸이 한 줄씩 나란히 보이고 빈 칸은 "비어 있음"으로 보인다

#### Scenario: 제품표 내보내기
- **WHEN** 엔지니어가 GIS 탭을 고르고 "내보내기"를 누르면
- **THEN** 엑셀 파일을 내려받고 "제품표_GIS.xlsx 를 내려받았습니다."가 보인다

### Requirement: 판정 규칙 화면
화면은 비교 방향, 위험 표현, 항목 이름, 문서 종류 사전을 탭으로 보여 주고, 줄마다 쓴 횟수(문서 종류는 분류한 문서 수)를 보여 주며 검색할 수 있어야 한다(SHALL). 엔지니어와 승인자에게는 탭마다 "규칙 추가", 줄마다 수정·삭제 단추와 사유를 받는 입력 창을 보이고, 저장하면 표와 "마지막 수정", 펼친 줄의 "수정 이력"을 새로 보여야 한다(SHALL). 다른 역할에게는 단추를 꺼 둔다.

#### Scenario: 규칙 검색
- **WHEN** 엔지니어가 비교 방향 탭에서 "정격 전류"를 검색하면
- **THEN** 그 항목의 규칙 줄만 방향, 시간 조건, 쓴 판정 수와 함께 보인다

#### Scenario: 문서 종류 규칙 탭
- **WHEN** 엔지니어가 판정 규칙 화면에서 문서 종류 탭을 누르고 "bidding"을 검색하면
- **THEN** 입찰 서식 줄만 파일 이름 표현, 첫 장 표현, 순서, 분류한 문서 수와 함께 보인다

#### Scenario: 화면에서 규칙 추가
- **WHEN** 엔지니어가 위험 표현 탭에서 "규칙 추가"를 눌러 표현·종류·조건·사유를 넣고 저장하면
- **THEN** 표에 새 줄이 보이고 "마지막 수정"이 그 엔지니어와 시각으로 바뀐다

#### Scenario: 화면에서 규칙 수정과 이력
- **WHEN** 엔지니어가 문서 종류 줄의 수정 단추로 표현을 고치고 사유를 넣어 저장한 뒤 그 줄을 펼치면
- **THEN** 수정 이력에 바뀌기 전·후 표현, 사유, 고친 사람이 보인다

#### Scenario: 화면에서 규칙 삭제
- **WHEN** 엔지니어가 위험 표현 줄의 삭제 단추를 누르고 사유를 넣어 확인하면
- **THEN** 그 줄이 표에서 사라진다

#### Scenario: 고칠 수 없는 역할
- **WHEN** 견적 담당이 판정 규칙 화면을 열면
- **THEN** 추가·수정·삭제 단추가 꺼져 있고 "엔지니어·승인자만 고칠 수 있습니다"가 보인다

### Requirement: 판정 탭 한꺼번에 확정
검토 상세 판정 탭은 줄 고르기 칸과, 고른 줄이 있으면 "n건 선택 · 제안대로 확정" 띠를 보여야 한다(SHALL). 확정하지 않은 준수 판정이 있으면 화면 아래 행동 줄에 "준수 n줄은 모두 확정"을, 판정 진행 묶음의 준수 칸에 "묶어서 확정"을 보이고, 누르면 확정하지 않은 준수 판정을 모두 제안대로 확정한다(SHALL). 담당자 확인 단계의 엔지니어가 아니면 보이지 않는다.

#### Scenario: 고른 줄 확정
- **WHEN** 엔지니어가 판정 2줄을 고르고 "제안대로 확정"을 누르면
- **THEN** 두 줄이 확정됨으로 바뀌고 "판정 2건을 일괄 확정했습니다." 알림이 보인다

#### Scenario: 준수 모두 확정
- **WHEN** 확정하지 않은 준수 판정이 있는 검토에서 아래 행동 줄의 "모두 확정"을 누르면
- **THEN** "판정 n건을 일괄 확정했습니다" 알림이 보이고 "모두 확정"이 사라지며 준수 판정은 모두 확정됨이다

### Requirement: TBE 준수표 화면
시스템은 검토 상세 머리의 "TBE 준수표" 단추로 TBE 준수표 화면을 열고, 판정 기준·포함 항목·항목 언어 선택, 요약(포함 항목, 준수, 일탈, 질의, 확인 필요, 그중 후보, 원문 위치 없음(제외)), 미리보기 표, "엑셀 내려받기"를 보여야 한다(SHALL). 판정 기준 "제출본 v1"은 승인된 실행에서만 고를 수 있다. 제출본 탭의 "이 판정으로 TBE 준수표 받기"도 이 화면을 연다.

#### Scenario: 넣을 줄 바꾸기
- **WHEN** 엔지니어가 TBE 준수표 화면에서 "확정 항목만"을 고르면
- **THEN** 미리보기와 포함 항목 수가 확정 항목만으로 바뀌고 파일 이름이 "…_확정만.xlsx"가 된다

#### Scenario: 엑셀 내려받기
- **WHEN** "엑셀 내려받기"를 누르면
- **THEN** .xlsx 파일이 내려받아지고 "…를 내려받았습니다 (n줄)." 알림이 보인다

### Requirement: 데이터시트 채우기 화면
시스템은 검토 상세 머리의 "데이터시트 채우기" 단추로 데이터시트 화면을 열고, 데이터시트 고르기, 요약(제출할 칸, 채움 · 확정, 채움 · 후보, 확인 필요), 채움 막대, 보기 거르기(전체 / 후보 / 확인 필요 / 확정), 표, "엑셀 내려받기"를 보여야 한다(SHALL). 후보 줄의 "확정"은 담당자 확인 단계의 엔지니어만 누를 수 있고, 누르면 그 칸이 확정으로 바뀐다. "영업에 넘기기"는 엔지니어에게만 열리고, 후보 칸이 남아 있으면 "후보 n칸을 먼저 확정" 안내와 함께 막는다. 넘기면 "영업 담당에게 넘겼습니다. 확인 필요 n칸은 비운 채로 넘어갑니다." 알림이 보이고, 넘긴 표는 단추가 "다시 넘기기"로 바뀌며 넘긴 시각을 보인다(`add-submission-package`).

#### Scenario: 칸 확정
- **WHEN** 엔지니어가 후보 줄의 "확정"을 누르면
- **THEN** 그 줄 상태가 확정이 되고 "칸 n … 값을 확정했습니다." 알림이 보이며 채움 · 확정 수가 1 늘어난다

#### Scenario: 확인 필요만 보기
- **WHEN** 보기에서 "확인 필요"를 고르면
- **THEN** 채운 값이 빈 줄만 보인다

#### Scenario: 데이터시트 영업에 넘기기
- **WHEN** 엔지니어가 후보 칸이 없는 데이터시트에서 "영업에 넘기기"를 누르면
- **THEN** "영업 담당에게 넘겼습니다" 알림이 보이고 단추가 "다시 넘기기"로 바뀐다

#### Scenario: 후보가 남아 넘기기 막힘
- **WHEN** 후보 칸이 남은 데이터시트를 열면
- **THEN** "영업에 넘기기"가 막혀 있고 "후보 n칸을 먼저 확정" 안내가 보인다

### Requirement: 예시 화면
시스템은 백엔드 기능이 없는 메뉴 화면(로그인, 입찰 이력·상세, 표준 문구, 팀 현황, 공지사항, 시스템 공지, 자료실, 설정)을 목업 레이아웃 그대로 고정 예시 데이터로 보여야 하고(SHALL), 로그인을 뺀 화면은 맨 위에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠를 보여야 한다(SHALL). 로그인은 앱 틀 밖이라 목업처럼 띠를 두지 않는다. 예시 화면의 동작은 저장하지 않아야 하며(MUST NOT) 다시 열면 처음 상태다. 입찰 금액과 가격 평가는 가린다. 사업 현황·상세(`add-project-status`)와 정답지·채점(`add-evaluation`)은 실제 화면이다.

#### Scenario: 예시 띠
- **WHEN** 왼쪽 메뉴에서 "입찰 이력"을 열면
- **THEN** 목업과 같은 입찰 이력 표와 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보이고 서버의 검토 API를 부르지 않는다

#### Scenario: 저장하지 않음
- **WHEN** 예시 화면에서 값을 바꾸는 동작(예: 공지 읽음, 설정 바꾸기)을 하고 화면을 다시 열면
- **THEN** 처음 상태로 보인다

#### Scenario: 금액 가림
- **WHEN** 입찰 이력이나 입찰 상세를 열면
- **THEN** 금액 칸은 숫자 대신 "영업 권한 필요"로 보인다

### Requirement: 처리 중 목록 새로고침
검토 목록과 홈은 처리 중인 검토가 하나라도 있으면 사용자가 새로고침하지 않아도 몇 초마다 실행 목록을 다시 불러와야 하고(SHALL), 처리 중 표시에 지금 단계와 백분율을 함께 보여야 한다(SHALL). 처리 중인 검토가 없으면 다시 부르지 않는다. 검토 목록의 처리 중인 줄은 단계 칩 아래에 진행 막대와 "n/전체 단계 수 지금 단계 · p %"를 보이고, 10분 넘게 진행이 없으면 막대와 글자를 주황으로 보인다(SHALL).

#### Scenario: 목록이 저절로 바뀜
- **WHEN** 처리 중인 검토가 있는 검토 목록을 열어 두고 그 검토의 처리가 끝나면
- **THEN** 새로고침하지 않아도 그 줄의 상태가 "처리 중"에서 담당자 확인 상태로 바뀐다

#### Scenario: 목록 줄 진행 막대
- **WHEN** 문서 읽기 단계에서 AI로 유형을 붙이는 중인 검토가 있는 검토 목록을 열면
- **THEN** 그 줄 단계 칸에 진행 막대와 "1/11 AI로 유형 붙이는 중 · p %"가 보이고, 10분 넘게 진행이 없는 줄은 주황으로 보인다

### Requirement: 긴 목록 페이지 번호
시스템은 표 아래 페이지 번호가 9쪽보다 많으면 처음 쪽, 끝 쪽, 지금 쪽 앞뒤 2쪽만 단추로 보이고 나머지는 "…"로 줄여야 한다(SHALL). 이전·다음 단추와 한 페이지 개수 고르기는 항상 화면 안에 보인다.

#### Scenario: 페이지가 많은 목록
- **WHEN** 판정 1,537줄을 10줄씩 보는 판정 탭에서 마지막 쪽 154를 누르면
- **THEN** 번호 단추는 9개 이하이고 154쪽 판정을 불러오며, 이전 단추를 누르면 153쪽이 된다

### Requirement: 검토 상세 문서 표
시스템은 검토 상세 머리글에 판정 대상 문서의 묶음을 "묶음 A·B"처럼 보이고, 판정 대상 문서가 없으면 "판정 문서 없음"을 눈에 띄게 보여야 한다(SHALL). 머리글의 "문서 n개"를 누르면 문서마다 파일 번호, 파일 이름, 문서 종류, 분류 방법(규칙·AI·사람), 묶음, 판정 대상 여부, 요구사항 수, 확인 필요 표시를 보이는 표가 열려야 한다(SHALL). 판정하지 않는 문서는 "판정 안 함"과 이유를 강조해 보여야 한다(SHALL). 이미 분석한 문서의 묶음은 화면에서 고치지 않는다. 엔지니어가 담당자 확인 단계 검토를 열면 창 아래 "문서 추가"에서 docx를 골라 분류 추천을 보고 묶음·문서 종류를 고른 뒤 "추가하고 다시 분석"을 누를 수 있어야 한다(SHALL). 누르면 창이 닫히고 검토는 처리 중 화면으로 바뀐다. 다른 사용자나 다른 단계에서는 "문서 추가"를 보이지 않는다. [제안]

#### Scenario: 판정 묶음 보기
- **WHEN** 묶음 A 문서 하나로 판정을 마친 검토 상세를 열면
- **THEN** 머리글에 "문서 1개"와 "묶음 A"가 보인다

#### Scenario: 문서 표 열기
- **WHEN** 엔지니어가 머리글의 "문서 1개"를 누르면
- **THEN** 창이 열리고 그 문서의 파일 이름, 문서 종류, 분류 방법(규칙 또는 AI), 묶음 A, 판정 대상, 요구사항 수가 보인다

#### Scenario: 판정하지 않는 문서
- **WHEN** 문서 목록에 없어 묶음 C로 분류된 문서만 있는 검토 상세를 열면
- **THEN** 머리글에 "판정 문서 없음"이 보이고, 문서 표에서 그 문서는 "판정 안 함"과 이유, "확인 필요"가 강조되어 보인다

#### Scenario: 문서 추가하고 다시 분석
- **WHEN** 엔지니어가 판정 1줄을 확정한 검토의 문서 표에서 docx 하나를 골라 "추가하고 다시 분석"을 누르면
- **THEN** 분석이 끝난 뒤 머리글에 "문서 2개"가 보이고, 확정한 그 줄은 "확정" 그대로이며, 이력에 "문서 추가"와 파일 이름이 보인다

#### Scenario: 승인자에게는 문서 추가 없음
- **WHEN** 승인자가 담당자 확인 단계 검토의 문서 표를 열면
- **THEN** "문서 추가" 칸이 보이지 않는다

### Requirement: 검토 등록 문서 분류 확인
화면은 검토 등록에서 문서를 고르면 분석 전 분류 추천을 불러와 문서 표의 문서 종류·묶음·언어 칸에 채우고, 판정 대상 여부와 추천 이유를 보여야 한다(SHALL). 사람은 문서마다 묶음(A~D)과 문서 종류를 고를 수 있고, 등록하고 분석을 시작하면 고른 값을 함께 보내야 한다(SHALL). 추천을 불러오는 동안에는 "분류하는 중"을 보이고, 실패하면 칸을 비우고 분석 중에 정한다고 알린다.

#### Scenario: 올린 문서의 분류 추천 보기
- **WHEN** 엔지니어가 검토 등록에서 docx 하나를 올리면
- **THEN** 몇 초 안에 그 줄에 문서 종류, 묶음, 언어, 판정 대상 여부와 이유가 보인다

#### Scenario: 묶음을 바꿔 시작
- **WHEN** 엔지니어가 묶음 C로 추천된 문서를 묶음 B로 바꾸고 등록하고 분석을 시작하면
- **THEN** 시작 요청에 그 문서의 묶음 B가 함께 가고, 그 줄에 "사람이 바꿈"이 보인다

### Requirement: 사업 현황 화면
화면은 사업 현황(SCR-04)에 실제 사업 목록을 보여야 한다(SHALL): 요약(진행 중 사업, 3일 내 제출 마감, 마감 지남)과 칸마다 설명 줄(범위·내 담당 수, 사업 이름·D-day), "내 사업 · 팀 전체", 찾기(상태, 국가, 제출 마감, 검색어), 사업 줄(순번, 사업명, 고객사 · 국가, 고객 입찰 번호, 제출 마감 D-n, 범위별 상태 칩, 내 역할, 영업). 요약 칸을 누르면 그 조건만 표에 남고, 다시 누르거나 "모두 보기"면 풀린다. 처리 중인 검토가 있는 동안 목록을 다시 불러온다. [결정] "등록 전 범위" 칸은 숨긴다.

#### Scenario: 사업 현황 열기
- **WHEN** 엔지니어가 자기 검토가 연결된 사업이 있는 상태로 왼쪽 메뉴의 사업 현황을 열면
- **THEN** 예시 띠 없이 그 사업 줄이 마감 가까운 순으로 범위 상태 칩, 내 역할 "엔지니어"와 함께 보인다

#### Scenario: 반려 칩
- **WHEN** 반려된 검토가 연결된 사업을 사업 현황에서 보면
- **THEN** 그 범위 칩이 빨간 "반려"로 보이고 마우스를 올리면 범위 · 담당이 보인다

#### Scenario: 팀 전체
- **WHEN** 사업 현황에서 "팀 전체"를 누르면
- **THEN** 고른 사용자와 관계없는 사업도 함께 보인다

#### Scenario: 요약 칸 설명 줄
- **WHEN** 3일 안에 마감하는 진행 중 사업 2개가 있는 상태로 사업 현황을 열면
- **THEN** "3일 내 제출 마감 2" 아래에 두 사업 이름과 D-day가 보인다

#### Scenario: 요약 칸으로 거르기
- **WHEN** 사업 현황에서 "3일 내 제출 마감" 칸을 누르면
- **THEN** 표에 그 두 사업만 남고 "3일 내 제출 마감 2건만 보는 중"과 "모두 보기"가 보이며, "모두 보기"를 누르면 모든 사업이 다시 보인다

### Requirement: 사업 상세 화면
화면은 사업 상세(SCR-05, `#/projects/<사업 번호>`)에 사업 정보와 개요(범위 카드)·담당자·일정·문서 탭을 실제 데이터로 보여야 한다(SHALL). 범위 카드를 누르면 상태에 맞는 화면(검토 상세, 협조 요청 현황, 결재)으로 간다. 사업 정보 고치기, 제출 완료 표시·취소, "이 사업에 RFP 등록", "인계 패키지 보기"(승인된 검토마다 내려받기·영업에 넘기기, 승인된 검토가 없으면 잠김) 단추가 있다. 지난 이력 탭은 예시 띠와 함께 예시로 남긴다.

#### Scenario: 범위 카드에서 검토로
- **WHEN** 사업 상세 개요에서 "판정 확인" 범위 카드를 누르면
- **THEN** 그 검토의 검토 상세가 열린다

#### Scenario: 이 사업에 RFP 등록
- **WHEN** 사업 상세에서 "이 사업에 RFP 등록"을 누르면
- **THEN** 검토 등록 화면이 "진행 중인 사업에 추가"와 그 사업이 고른 채로 열린다

#### Scenario: 제출 완료 단추
- **WHEN** 결재 대기 검토가 있는 사업 상세를 열면
- **THEN** "제출 완료로 표시" 단추가 잠겨 있고 모든 검토가 승인되어야 한다는 안내가 보인다

#### Scenario: 지난 이력은 예시
- **WHEN** 사업 상세에서 지난 이력 탭을 열면
- **THEN** 탭 안에 "예시 화면 · 실제 데이터와 연결되지 않음" 띠가 보인다

#### Scenario: 사업 상세에서 인계 패키지
- **WHEN** 결재가 승인된 검토 하나가 연결된 사업 상세에서 "인계 패키지 보기"를 누르면
- **THEN** 창에 그 검토 번호·이름과 [인계 패키지 내려받기]가 보인다

#### Scenario: 승인 전 잠김
- **WHEN** 승인된 검토가 없는 사업 상세를 열면
- **THEN** "인계 패키지 보기"가 잠겨 있고 "결재가 승인된 검토가 없습니다"가 이유로 보인다

### Requirement: 검토 등록 사업 연결
화면은 검토 등록의 검토 정보 단계에 "사업 연결"(새 사업 만들기 / 진행 중인 사업에 추가)을 보여야 한다(SHALL). 새 사업은 사업명을 받고, 진행 중인 사업은 제출 완료가 아닌 사업 목록에서 고른다. 사업을 고르면 고객사·국가·마감 칸을 사업 값으로 미리 채우고 사람이 고칠 수 있다. 검토 머리글의 사업명을 누르면 사업 상세로 간다.

#### Scenario: 사업 고르면 미리 채움
- **WHEN** 검토 등록에서 "진행 중인 사업에 추가"로 고객사가 든 사업을 고르면
- **THEN** 고객사·국가·마감 칸이 그 사업 값으로 채워지고 검토명 안내가 "<사업명> · 설비 범위"로 바뀐다

#### Scenario: 머리글에서 사업으로
- **WHEN** 사업에 연결된 검토의 검토 상세 머리글에서 사업명을 누르면
- **THEN** 그 사업의 사업 상세가 열린다

### Requirement: 실행 기록 화면

#### Scenario: 상업 조건 원문 펼치기

- **THEN** 그 줄 아래에 원문 전체가 값 "0.5 %"를 강조해 보이고 원문 위치 전체(파일 이름 포함)가 보이며, 다시 누르면 접힌다

#### Scenario: 상업 영향 펼치기

- **THEN** 그 줄 아래에 일탈 설명 전체와 원문 위치가 보이고, 그 줄의 "판정 →"을 누르면 펼치지 않고 판정 탭으로 간다

### Requirement: 판정 탭의 공학 검산 표시
시스템은 판정 탭에서 공학 규칙 검산(FR-12) 결과를 보여야 한다(SHALL). 검산이 위반이거나 확인 필요인 최대 순간 전류·단시간 전류 줄에는 판정 표에 "검산 위반" 또는 "검산 확인 필요" 표시를 붙이고, 판정 탭 머리에 위반·확인 필요 검산 수와 그 결과로 꼬리표를 붙인 항목 수를 함께 보인다(검산 하나는 두 항목에 표시). 판정 상세 화면에는 서버가 저장한 값으로 계산식, 원문 값, 결과(통과·위반·확인 필요와 이유)를 보인다. 화면은 값을 새로 계산하거나 판정을 바꾸지 않는다(CR-01). [결정]

- **THEN** 그 최대 순간 전류 줄에 "검산 위반"이 보이고 차단 전류 줄에도 "검산 위반"이 보이며, 머리에 "공학 검산 위반 1건(표시한 항목 2개) · 확인 필요 1건(표시한 항목 2개)"이 보인다

#### Scenario: 검산 계산식 보기
- **WHEN** 그 줄을 눌러 판정 상세 화면을 열면
- **THEN** "공학 검산" 칸에 "50 kA × 2.5 = 125 kA"와 원문 "100 kA", "위반"이 보인다

#### Scenario: 통과한 검산

- **THEN** 표에는 검산 표시가 없고, 판정 상세 화면 "공학 검산" 칸에 "통과"와 계산식이 보인다

### Requirement: 검토 목록 내가 올린 결재 보기
검토 목록은 담당 범위에 "내가 올린 결재" 보기를 두어, 머리글에서 고른 사용자가 상신한 검토만 결재 대기·반려·승인으로 나눠 개수와 함께 보여야 한다(SHALL). 이 보기의 각 줄에는 결재자와 상신 후 날 수 또는 결정 시각을 보여야 한다(SHALL). 결재자 전용 보기와 새 메뉴는 만들지 않는다. [결정]

#### Scenario: 지금 채점하기

화면은 판정 탭에서 지난 사람 판정이 있는 줄의 판정 칸에 "지난 확정 <판정>" 꼬리표를 보이고, 지금 판정과 다르면 "지난 확정과 다름"으로 눈에 띄게 해야 하며(SHALL), 판정 상세 화면에 지난 검토 번호(링크), 판정, 사람, 날짜, 사유를 보여야 한다(SHALL). 다른 줄이 있으면 칩 "지난 확정과 다름 n"으로 그 줄만 거를 수 있어야 한다(SHALL). [제안]

### Requirement: 사전 추가 제안 화면
화면은 위험 조건 탭 "사람이 찾은 특이 요구"에서 놓친 표현과 메모를 넣어 제안하고 이 검토의 제안(표현, 찾은 곳, 상태)을 보여야 하며, 판정 규칙 화면 "사람이 제안한 표현"에서 제안을 확인 대기부터 보이고 엔지니어·승인자에게 [반영]·[반려]를 보여야 한다(SHALL). 판정 규칙 화면 목록은 칸 이름 줄(제안일 · 제안한 표현 · 제안한 곳 · 상태 · 처리)을 두고 모든 줄을 같은 칸 폭으로 그려, 확인 대기 줄의 [반영]·[반려]와 끝난 제안의 처리 날짜·사람이 같은 처리 칸에 놓인다. 판정 규칙 화면에서 제안 줄을 누르면 줄 아래에 그 표현이 나온 원래 문장 전체(표현 강조)와 원문 위치 모두, 메모·반려 사유를 펼치고 다시 누르면 접는다. [반영]·[반려]·링크를 눌러서는 펼치지 않는다. [반영]은 표현을 채운 규칙 추가 창을 연다. 예시 띠를 붙이지 않는다. [제안]

#### Scenario: 제안하고 반영하기
- **WHEN** 엔지니어가 위험 조건 탭에서 문서에 있는 표현을 제안하고, 판정 규칙 화면에서 그 제안을 반영하면
- **THEN** 위험 조건 탭에 "확인 대기"로 보였던 제안이 판정 규칙 화면에서 "반영"으로 바뀌고 위험 표현 탭에 그 표현이 보인다

#### Scenario: 제안 목록 칸 맞춤
- **WHEN** 확인 대기 제안과 반영된 제안이 함께 있는 판정 규칙 화면을 열면
- **THEN** 목록 위에 "제안한 표현"·"제안한 곳"·"상태"·"처리" 칸 이름이 보이고, 두 줄의 상태 칸이 같은 가로 위치에서 시작한다

#### Scenario: 제안 줄 펼쳐 원문 보기
- **WHEN** 엔지니어가 판정 규칙 화면에서 문장 일부만 제안된 줄을 누르면
- **THEN** 줄 아래에 원래 문장 전체가 보이고 제안한 표현이 강조되며 원문 위치가 보이고, 다시 누르면 접힌다

### Requirement: 검토 도우미 창
화면은 분석이 끝난 검토 상세 머리글에 "검토 도우미" 단추를 두고, 누르면 오른쪽 창에 질문 칸, 예시 질문(AI가 없어도 결과가 나오는 영어 낱말), 상태 한 줄("AI 답변 (근거와 대조함)" 또는 "검색어로 찾은 결과 (까닭)", 뺀 문장 수), 답 문장(문장마다 [1]처럼 근거 조항 번호), 근거 조항(번호, 원문 위치, 유형 또는 판정 값, 원문), 접어 둔 "찾은 방법 보기"를 보여야 한다(SHALL). 맞는 조항이 없으면 "일치하는 조항이 없습니다."를 보이고, 질문에 한글이 있으면 영어 낱말로 찾아 보라고 덧붙인다. 창에는 고치기 단추가 없다. [제안]

#### Scenario: 도우미에 묻기
- **WHEN** 엔지니어가 검토 도우미 창에서 "ambient temperature"를 물으면
- **THEN** 창에 그 글자가 들어간 근거 조항과 원문 위치, 상태 한 줄이 보인다

#### Scenario: 맞는 조항이 없을 때
- **WHEN** AI 없이 도는 검토 도우미 창에서 "시험 입회 조건이 있는 조항"을 물으면
- **THEN** "일치하는 조항이 없습니다."와 영어 낱말로 찾아 보라는 안내가 보이고 근거 조항은 없다

### Requirement: 버린 AI 설명 표시
화면은 실행 기록 화면 검토 줄에 버린 AI 설명 수를 보이고(0이면 보이지 않음), 위험 조건 탭에서 설명을 버린 줄의 설명 칸에 "AI 설명 버림"과 이유(근거 위치 불일치, 근거에 없는 인용, 근거에 없는 숫자, 형식 오류)를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 버린 설명 보기
- **WHEN** 설명 하나가 근거에 없는 숫자로 버려진 검토의 위험 조건 탭과 실행 기록 화면을 열면
- **THEN** 그 위험 조건 줄에 "AI 설명 버림 · 근거에 없는 숫자"가, 실행 기록 줄에 "AI 설명 버림 1"이 보인다

### Requirement: 한꺼번에 확정에서 뺀 줄 알림
화면은 한꺼번에 확정 뒤 확정한 줄 수와 함께 뺀 줄 수와 이유별 수(검산, 숫자 불일치, 값 없음)를 알리고 한 줄씩 확인하라고 안내해야 한다(SHALL). [제안 11-01]

#### Scenario: 뺀 줄 알림
- **WHEN** 엔지니어가 고른 줄 중 1줄이 검산 위반으로 빠진 채 한꺼번에 확정되면
- **THEN** "1건은 제외했습니다(검산 1)"와 한 줄씩 확인하라는 안내가 보인다

### Requirement: AI 검증 표시
화면은 위험 조건 탭에서 검증이 확인 필요인 설명 옆에 "AI 검증: 확인 필요"를, 실행 기록 화면 검토 줄에 검증 확인 필요 수를(0이면 보이지 않음) 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 검증 확인 필요 보기
- **WHEN** 설명 하나가 검증에서 확인 필요인 검토의 위험 조건 탭과 실행 기록 화면을 열면
- **THEN** 그 위험 조건 줄에 "AI 검증: 확인 필요"가, 실행 기록 줄에 "검증 확인 필요 1"이 보인다

### Requirement: 요구사항 정답지 고르기 화면
화면은 정답지·채점 화면 정답지 탭에서 유형 정답지와 따로 요구사항 정답지 목록(이름, 대상 문서, 줄 수, 만든 이)을 보이고 하나를 골라 채점하게 해야 한다(SHALL). 코드가 만든 정답지에는 "자동 생성 · 검수 전"을 붙이고, 판정 줄이 없는 검토는 "판정 0줄"로 보이되 처음에는 넣지 않는다. 요구사항 정답지로 채점하면 채점 결과에 K1·K2·K3·K10이 보인다. [제안 11-01]

#### Scenario: 요구사항 정답지로 채점
- **WHEN** 코드 자동 요구사항 정답지가 있는 상태에서 정답지 탭을 열어 그 정답지를 고르고 "지금 채점하기"를 누르면
- **THEN** 정답지에 "자동 생성 · 검수 전"과 대상 문서가 보이고, 채점 결과 탭에 K1 값이 보인다

### Requirement: 뜻 찾기 표시
화면은 위험 조건 탭에 "사전 추가 후보"(문장, 유사 문장·표현, 유사도, 원문 위치, [사전 추가 제안])와 유사 문장 검색 상태(안 함·건너뜀)를 보이고, 판정 탭 지난 확정 꼬리표에 뜻으로 찾은 것이면 "유사도 0.93"처럼 점수를 붙이며, 판정 규칙 화면 "항목 이름" 탭에 연결 후보와 엔지니어·승인자용 [동의어로 추가]·[숨기기]를 보여야 한다(SHALL). [제안 11-01]

#### Scenario: 사전 추가 후보 보기
- **WHEN** 사전 추가 후보가 있는 검토의 위험 조건 탭을 열면
- **THEN** 후보 문장과 유사도, 유사 문장이 보이고 [사전 추가 제안]을 누르면 아래 제안 칸에 그 문장(100자까지)과 메모가 채워진다

#### Scenario: 항목 연결 후보 받아들이기
- **WHEN** 엔지니어가 판정 규칙 화면 항목 이름 탭의 연결 후보에서 [동의어로 추가]를 누르면
- **THEN** 후보가 목록에서 빠지고 알림이 보인다

### Requirement: 공통 목록 표의 순번
시스템은 공통 목록 표 부품으로 그린 표의 맨 왼쪽에 "순번" 칸을 보여야 한다(SHALL). 번호는 쪽을 넘겨도 이어지고(둘째 쪽 첫 줄 = 쪽 크기 + 1), 거르기를 바꾸면 거른 결과의 1부터 다시 센다. 표 부품은 로딩 중·빈 목록·오류 상태를 공통 규칙대로 보인다. [결정]

#### Scenario: 쪽을 넘겨도 순번이 이어짐
- **WHEN** 부품 견본 화면에서 12줄짜리 표를 10줄씩 보다가 2쪽으로 넘기면
- **THEN** 첫 줄의 순번이 11이다

#### Scenario: 빈 목록
- **WHEN** 줄이 없는 표를 보면
- **THEN** 표 안에 그 표의 빈 목록 문장이 한 줄 보인다

### Requirement: 알림 쌓기
시스템은 알림을 두 가지로 보여야 한다(SHALL). 사용자가 방금 누른 동작의 결과 알림은 화면 아래 가운데에 하나만 보이고 4초 뒤 사라지며, 새 결과가 오면 바꿔 끼운다. 아래에 행동 줄이 붙은 화면에서는 그 줄 위에 보인다. 시스템이 알려 주는 알림(분석 끝남·멈춤 등)과 오류 알림은 화면 오른쪽 위에 위에서 아래로 쌓아 모두 보이며, 성공·안내는 4초 뒤 사라지고 오류는 닫기 전까지 남는다. 같은 문장의 쌓기 알림이 이미 보이면 하나만 보인다. [결정]

#### Scenario: 알림 두 개
- **WHEN** 부품 견본 화면에서 쌓기 알림 두 개를 잇달아 띄우면
- **THEN** 두 알림이 모두 오른쪽 위에 보이고 먼저 띄운 것이 위에 있다

#### Scenario: 오류 알림은 남음
- **WHEN** 오류 알림을 띄우고 5초가 지나면
- **THEN** 오류 알림은 남아 있고, 닫기를 누르면 사라진다

#### Scenario: 동작 결과는 아래 가운데
- **WHEN** 부품 견본 화면에서 동작 결과 알림 두 개를 잇달아 띄우면
- **THEN** 화면 아래 가운데에 나중 알림 하나만 보이고 4초 뒤 사라진다

### Requirement: 잠긴 단추의 이유
시스템은 권한이나 단계 때문에 누를 수 없는 공통 단추를 숨기지 않고 잠근 채 이유를 보여야 한다(SHALL). 이유는 마우스를 올리면 보이고 화면 읽기 도구로도 읽힌다. [결정]

#### Scenario: 잠긴 단추에 이유
- **WHEN** 부품 견본 화면의 잠긴 단추를 보면
- **THEN** 단추는 눌리지 않고 "승인자만 결정할 수 있습니다" 이유가 단추 설명으로 붙어 있다

### Requirement: 공통 창 닫기
시스템은 공통 창 부품으로 연 창을 Esc, 창 바깥 누르기, 닫기 단추로 닫아야 한다(SHALL). 창이 열리면 첫 입력 칸(없으면 창)에 초점이 가고, 닫히면 창을 연 단추로 초점이 돌아간다. [결정]

#### Scenario: Esc로 창 닫기
- **WHEN** 부품 견본 화면에서 창을 열고 Esc를 누르면
- **THEN** 창이 닫히고 창을 연 단추에 초점이 있다

### Requirement: 머리글 분석 진행 표시
시스템은 처리 중인 검토가 하나라도 있으면 모든 화면 머리글에 분석 진행 단추("분석 n건 · p %", p는 처리 중 검토 진행률의 평균)를 보여야 한다(SHALL). 단추를 누르면 작은 창에 검토마다 검토 번호·이름, 단계 문장, 진행 막대, 지난 시간을 보이고 처리 상태 화면으로 가는 링크를 둔다. 처리 중 검토가 없으면 단추를 보이지 않는다. 멈춤 안내 기준을 넘은 검토가 있으면 단추를 주황으로 보인다. [결정]

#### Scenario: 머리글 분석 진행 표시
- **WHEN** 처리 중 검토가 1건 있을 때 아무 화면을 열면
- **THEN** 머리글에 "분석 1건"과 진행률이 보이고, 누르면 작은 창에 그 검토 번호와 단계 문장, 진행 막대가 보인다

#### Scenario: 처리 중 없으면 숨김
- **WHEN** 처리 중 검토가 없을 때 화면을 열면
- **THEN** 머리글에 분석 진행 단추가 없다

### Requirement: 분석 끝남 안내
시스템은 머리글에 보이던 처리 중 검토가 끝나면 화면 오른쪽 위 알림 쌓기에 "분석이 끝났습니다" 알림과 검토로 가는 링크를 띄워야 한다(SHALL). 처리가 실패하면 "분석이 멈췄습니다" 오류 알림을 띄우고, 사람이 취소한 검토는 알리지 않는다. 화면을 처음 열 때 이미 끝나 있던 검토는 알리지 않는다. [결정]

#### Scenario: 끝남 안내
- **WHEN** 머리글에 보이던 처리 중 검토의 분석이 끝나면
- **THEN** "분석이 끝났습니다" 알림이 오른쪽 위에 보이고, 링크를 누르면 그 검토 상세로 간다

### Requirement: 검토 상세 아래 행동 줄
시스템은 처리를 마친 검토 상세 화면 아래에 늘 보이는 행동 줄을 두어야 한다(SHALL). 담당자 확인 단계에서는 확정 안 한 판정 수, 확정 안 한 준수가 있으면 "준수 n줄은 모두 확정"(엔지니어만), 데이터시트 빈칸이 있으면 그 수와 "데이터시트 채우기", "결재 상신"(엔지니어가 아니면 잠근 채 이유)을 보인다. 다른 단계에서는 확정·상신 단추 없이 단계 이름과 결재자를 한 줄로 보이고, 승인된 검토는 잠긴 "제출본 v1 확정"을 보인다. [결정]

#### Scenario: 아래 행동 줄로 한꺼번에 확정
- **WHEN** 담당자 확인 단계에 확정 안 한 준수 45줄이 있는 검토에서 엔지니어가 아래 줄의 "모두 확정"을 누르면
- **THEN** "판정 45건을 일괄 확정했습니다" 알림이 보이고 아래 줄에서 "모두 확정"이 사라진다

#### Scenario: 단계별 아래 줄
- **WHEN** 엔지니어가 승인된 검토 상세를 열면
- **THEN** 아래 줄에 "승인됨"이 보이고 "결재 상신"과 "모두 확정" 단추가 없다

### Requirement: 판정 상세 화면
화면은 판정 줄을 누르면 판정 상세 화면(주소에 검토·판정 번호와 판정 목록 거르기)을 열어 판정 배지·항목 이름, 거른 목록 안의 자리("판정 n / 전체"), 원문(파일 이름·언어, 위치가 둘 이상이면 위치 탭, 절 번호·제목, 그 줄과 앞뒤 2줄, 표 위치면 표 한 줄)을 보여야 한다(SHALL). ↑↓로 같은 거르기의 이전·다음 판정을 보고, Esc나 판정 목록으로를 누르면 같은 거르기·같은 쪽의 판정 목록으로 돌아간다(SHALL). [결정]

#### Scenario: 판정 상세 화면 열기
- **WHEN** 일탈 후보 판정 2줄이 있는 검토의 판정 목록에서 일탈 후보 칩을 고르고 첫 줄을 누르면
- **THEN** 주소가 그 판정의 판정 상세 주소가 되고 "판정 1 / 2", 요구값·제품값·비교 방향이 보인다

#### Scenario: 이전·다음과 목록으로
- **WHEN** 판정 상세 화면에서 ↓ 키를 누르고 Esc를 누르면
- **THEN** 같은 거르기의 다음 판정이 보인 뒤, 같은 거르기·같은 쪽의 판정 목록으로 돌아가고 보던 판정 줄이 강조된다

#### Scenario: 위치 탭과 원문 앞뒤 줄
- **WHEN** 원문 위치가 두 곳인 판정에서 두 번째 위치 탭을 누르면
- **THEN** 그 위치의 줄 번호와 앞뒤 줄이 보이고 그 줄이 강조된다

#### Scenario: 이 검토에 없는 판정
- **WHEN** 이 검토에 없는 판정 번호로 판정 상세를 열면
- **THEN** "이 검토에 없는 판정입니다"와 판정 목록으로 가는 링크가 보인다

### Requirement: 판정 상세 근거와 출처
화면은 판정 상세에 비교(요구값·부등호·제품값), 판정 근거(비교 방향과 판정 규칙 보기, 적용 규칙, 같은 요구가 나온 위치 수, 제품값 출처, 팀 가정이면 "팀 가정"), 판정 출처(시스템 제안, 요구사항을 찾은 방법과 신뢰도, 담당자 확정, 지난 확정)를 보여야 한다(SHALL). 질의 후보는 "질의 초안" 꼬리표, 목록 문장이 있으면 그 문장, 보증값 작성 줄은 후보 값과 데이터시트로 가는 링크를 보인다(SHALL). 화면은 값을 계산하지 않는다(CR-01).

#### Scenario: 팀 가정 표시
- **WHEN** 팀 가정 비교값으로 한 판정의 판정 상세를 열면
- **THEN** 제품값 출처 옆에 "팀 가정"이 보인다

#### Scenario: 찾은 방법과 신뢰도
- **WHEN** AI가 찾은 요구사항의 판정 상세를 열면
- **THEN** 판정 출처에 "AI 추출"과 신뢰도가 보인다

### Requirement: 판정 상세에서 확정과 바꾸기
엔지니어는 담당자 확인 단계에서 판정 상세 아래 줄의 "제안대로 확정"으로 판정을 확정하고 다음 확정 안 한 판정으로 넘어가거나, "판정 변경" 창에서 새 판정과 사유(필수)로 바꿀 수 있어야 한다(SHALL). 다른 단계이거나 엔지니어가 아니면 두 단추를 잠그고 이유를 보여야 한다(SHALL).

#### Scenario: 제안대로 확정하고 다음 판정
- **WHEN** 엔지니어가 확정 안 한 판정의 판정 상세에서 제안대로 확정을 누르면
- **THEN** "판정을 제안대로 확정했습니다." 알림이 보이고 다음 확정 안 한 판정이 열린다

#### Scenario: 단계 때문에 못 고침
- **WHEN** 승인 대기 단계 검토의 판정 상세를 열면
- **THEN** 판정 변경·제안대로 확정이 잠기고 이유가 보인다

#### Scenario: 사유 필수
- **WHEN** 판정 변경 창에서 새 판정을 고르고 사유를 비운 채 적용을 누르면
- **THEN** "판정을 바꾸려면 사유를 적어 주세요."가 보이고 판정은 그대로다

### Requirement: 협조 요청 찾기
화면은 협조 요청 탭 이름 옆에 부서별 건수를 보이고, 검색 영역(사업, 그 사업으로 좁혀지는 RFP 검토, 회신 전체·회신 대기·회신 기한 지남·회신 완료, 수신 주소, 검색어)과 초기화·검색 단추, 걸린 조건 칩(누르면 그 조건만 풂)과 건수를 보여야 한다(SHALL). 요약 줄 상태를 누르면 그 상태만 거른다. 상태 칸 아래에 회신 시각 또는 회신 기한(지나면 빨강)을 보인다. 맞는 요청이 없으면 요청 항목에 "조건에 맞는 요청이 없습니다." 문장만 보인다(SHALL). 조건은 검색 영역 초기화나 조건 칩으로 푼다.

#### Scenario: 검색 영역으로 거르기
- **WHEN** 견적 요청 8건 중 Thai Binh 사업이 5건일 때 사업을 Thai Binh으로 고르고 검색을 누르면
- **THEN** 5건만 보이고 "사업: Thai Binh" 칩과 "5건"이 보이며, 칩을 누르면 8건으로 돌아간다

#### Scenario: 회신 기한 지남
- **WHEN** 회신 기한이 지난 요청 2건이 있고 회신에서 "회신 기한 지남"을 고르고 검색하면
- **THEN** 2건만 보이고 상태 칸에 빨간 회신 기한이 보인다

#### Scenario: 조건에 맞는 요청 없음
- **WHEN** 맞는 요청이 없는 검색어로 검색하면
- **THEN** "조건에 맞는 요청이 없습니다." 문장만 보이고 조건 지우기 단추는 없다

### Requirement: 협조 요청 RFP별 보기
화면은 협조 요청 보기를 담당별과 RFP별로 고를 수 있어야 하고(SHALL), RFP별에서는 부서 탭과 상관없이 검색 조건에 맞는 모든 부서 요청을 검토마다 접는 묶음(검토 번호·이름·사업명, 부서별 수, 회신 받은 수 / 전체, 기한 지남 수 또는 협조 완료, 이 검토에 요청)으로 보인다(SHALL). RFP별 보기도 쪽을 나눠야 한다(SHALL): 한 쪽은 요청 10건(5·10·20건 중 고름)이고 아래에 쪽 번호 줄을 두며, 한 검토의 요청은 이어진 쪽에만 있고 묶음 머리 숫자는 그 검토의 거른 요청 전체로 센다.

#### Scenario: RFP별 묶어 보기
- **WHEN** 검토 두 개에 요청이 있을 때 RFP별을 고르면
- **THEN** 검토마다 묶음이 보이고 묶음 머리에 "회신 m / n"이 보이며, 묶음을 접고 펼 수 있다

#### Scenario: RFP별 쪽 나누기
- **WHEN** 거른 요청이 10건보다 많을 때 RFP별을 고르면
- **THEN** 첫 쪽에 요청 10건까지만 보이고 아래 쪽 번호 줄로 다음 쪽을 열 수 있으며, 묶음 머리의 "회신 m / n"은 그 검토의 요청 전체 수다

### Requirement: 협조 요청 내보내기 단추
화면은 협조 요청 제목 옆 "내보내기"를 누르면 지금 거른 요청 전부(쪽 나누기와 상관없이)를 엑셀로 내려받게 해야 한다(SHALL). 거른 요청이 없으면 단추를 잠근다.

#### Scenario: 협조 요청 내보내기
- **WHEN** 거른 요청이 5건일 때 내보내기를 누르면
- **THEN** 5건의 번호로 엑셀을 요청해 내려받고 "협조요청_견적 담당.xlsx를 만들었습니다." 알림이 보인다

### Requirement: 제품 상세 화면
화면은 `#/products/<코드>` 주소에 제품 하나의 상세(코드, 제품군, 설계 사례, 값 종류 · 출처, 요약 칸 제품·근거 상태(팀 가정 수, 빈칸 수)·쓰임(쓰이는 검토 수, 값이 없어 막힌 판정 수, 제안 포인트 수), 탭 정격·치수·운송·쓰인 곳·현장 이력)를 보여야 한다(SHALL). 정격 탭 칸마다 비교 방향과 근거(출처·팀 가정·비어 있음)를 보인다. 수정 요청은 잠그고, 없는 코드면 "제품표에 없는 제품입니다"와 제품표로 가는 단추를 보인다(SHALL). [결정]

#### Scenario: 제품 상세 화면 열기
- **WHEN** 엔지니어가 제품표에서 GIS 제품 코드를 누르면
- **THEN** 주소가 `#/products/<코드>`가 되고 정격 탭에 정격 전압 값과 비교 방향이 보인다

#### Scenario: 쓰인 곳
- **WHEN** 검토 하나에 쓰인 제품의 상세 화면에서 쓰인 곳 탭을 누르면
- **THEN** 그 검토 번호와 판정 수가 보이고, 누르면 검토 상세로 간다

#### Scenario: 팀 가정 표시
- **WHEN** 팀 가정 비교값 2칸이 있는 제품의 상세 화면을 열면
- **THEN** 근거 상태에 "팀 가정 2"가 보이고 정격 탭 그 칸에 "팀 가정"이 붙는다

#### Scenario: 막힌 판정
- **WHEN** 비교 칸이 비어 확인 필요가 된 판정 1줄이 있는 제품의 상세 화면을 열면
- **THEN** "값이 없어 막힌 판정 1"과 그 판정 항목이 보인다

#### Scenario: 없는 제품
- **WHEN** 제품표에 없는 제품 코드 주소를 열면
- **THEN** "제품표에 없는 제품입니다"와 제품표로 가는 단추가 보인다

### Requirement: 요구 조건으로 찾기
화면은 제품표에서 "요구 조건으로 찾기"를 켜면 정격 전압·정격 전류·단시간 견딤 전류 칸을 보이고, 입력한 값 이상인 제품만 "요구 충족" 칸과 함께 보여야 한다(SHALL). 값이 빈 제품은 맞음으로 치지 않는다. 단위는 바꾸지 않는다(CR-10). "RFP 검토 찾기" 창에서 검토를 거르고 골라 [요구값 넣기]를 누르면 그 검토 판정의 요구값을 칸에 넣는다(SHALL). [제안]

#### Scenario: 요구 조건으로 거르기
- **WHEN** 엔지니어가 요구 조건으로 찾기를 켜고 정격 전류에 4000을 넣으면
- **THEN** 정격 전류가 4000 이상인 제품만 남고 "요구 충족" 칸에 맞음이 보인다

#### Scenario: RFP 검토 찾기
- **WHEN** 요구값 145 kV · 3150 A · 40 kA인 검토를 RFP 검토 찾기에서 고르고 [요구값 넣기]를 누르면
- **THEN** 요구 조건 칸에 세 값이 들어가고 표가 맞는 제품으로 줄어든다

### Requirement: 개정 안내 띠
화면은 문서를 더해 다시 분석한 검토의 판정 탭 위에 개정 안내 띠("문서 추가 반영 · 파일 이름 · 판정 n건 변경 · m줄 추가 · k줄 사라짐 · 시각")와 [변경 항목만 보기]·닫기를 보이고, 판정 칸에 "바뀜(개정)"·"추가(개정)", 제목 줄에 "개정 n 반영", 판정 상세에 같은 꼬리표를 보여야 한다(SHALL). 닫으면 그 개정은 그 브라우저에서 다시 보이지 않는다. 홈 "어제 이후 바뀐 것"에 문서를 더해 다시 분석한 검토 줄을 보인다.

#### Scenario: 개정 안내 띠
- **WHEN** 문서를 더해 다시 분석해 판정 2줄이 바뀐 검토의 판정 탭을 열면
- **THEN** 개정 안내 띠에 파일 이름과 "판정 2건 변경"이 보이고, [변경 항목만 보기]를 누르면 바뀐 줄만 남으며 그 줄에 "바뀜(개정)"이 보인다

#### Scenario: 개정 안내 닫기
- **WHEN** 개정 안내 띠를 닫고 검토 상세를 다시 열면
- **THEN** 띠가 보이지 않고 제목 줄의 "개정 1 반영"은 그대로 보인다

#### Scenario: 홈에 문서 추가
- **WHEN** 어제 이후 문서를 더해 다시 분석한 내 검토가 있는 상태로 홈을 열면
- **THEN** "어제 이후 바뀐 것"에 "문서 추가 1"이 보이고, 펼친 줄의 [바뀐 줄 보기]가 그 검토의 변경 항목만 보기로 간다

### Requirement: 판정 상세에서 질의 보냄
화면은 질의 후보 판정의 판정 상세에 "질의 초안" 또는 "질의 보냄 · MM-DD" 꼬리표와 [질의 보냄 표시]/[되돌리기] 단추를, 판정 표의 질의 후보 줄에 같은 꼬리표를 보여야 한다(SHALL). 엔지니어가 아니거나 담당자 확인 단계가 아니면 단추를 잠그고 이유를 보인다. 질의 후보가 아닌 판정에는 질의 칸이 없다.

#### Scenario: 질의 보냄 표시
- **WHEN** 담당자 확인 단계의 질의 후보 판정 상세에서 엔지니어가 [질의 보냄 표시]를 누르면
- **THEN** 꼬리표가 "질의 보냄 · 오늘 날짜"가 되고, 판정 목록으로 돌아가면 그 줄에도 같은 꼬리표가 보인다

#### Scenario: 질의 보냄 되돌리기
- **WHEN** 질의 보냄으로 표시한 판정 상세에서 [되돌리기]를 누르면
- **THEN** 꼬리표가 다시 "질의 초안"이 된다

#### Scenario: 승인자는 잠김
- **WHEN** 승인자가 질의 후보 판정 상세를 열면
- **THEN** [질의 보냄 표시]가 잠겨 있고 "기술 검토 엔지니어만 고칠 수 있습니다"가 이유로 보인다

### Requirement: 요약 문장은 코드가 쓴다
시스템은 검토 요약과 홈 요약 문장을 정해진 틀에 숫자·이름·날짜를 채워 만들어야 한다(SHALL). 언어 모델을 부르지 않고, 같은 데이터면 같은 문장을 돌려준다. 응답은 문장마다 글자·링크·강조 조각 목록과 만든 시각, 쓴 주체 "CODE"를 담는다. [결정 Q1]

#### Scenario: 같은 데이터면 같은 문장
- **WHEN** 데이터가 바뀌지 않은 검토의 요약을 두 번 부르면
- **THEN** 두 응답의 문장 조각이 같고, 쓴 주체는 CODE다

#### Scenario: AI를 부르지 않음
- **WHEN** 언어 모델 호출이 실패하도록 바꾼 채 요약을 부르면
- **THEN** 요약 문장이 그대로 나온다

### Requirement: 검토 요약
시스템은 `GET /runs/{id}/summary`로 검토 요약을 최대 4문장 돌려줘야 한다(SHALL). 반려·승인 단계 안내, 꼭 볼 판정 수(일탈·질의·확인 필요, 판정 탭 수와 같음)와 상신 권장일(마감 2일 전), 먼저 볼 일탈 후보 두 줄(판정 상세 링크), 마지막 개정의 줄 수, 데이터시트 빈 작성 칸 수를 이 순서로 쓴다. 처리 중이면 아직 요약할 판정이 없다는 한 문장이다. 없는 검토는 404.

#### Scenario: 꼭 볼 판정과 상신 권장일
- **WHEN** 마감이 11-10이고 일탈 후보 2건·질의 후보 1건·확인 필요 3건인 검토의 요약을 부르면
- **THEN** "꼭 볼 것 6줄은 일탈 후보 2건, 질의 후보 1건, 확인 필요 3건입니다. 상신 권장일은 11-08입니다."가 나오고 11-08은 강조 조각이다

#### Scenario: 먼저 볼 일탈 후보 링크
- **WHEN** 일탈 후보가 3건인 검토의 요약을 부르면
- **THEN** 두 줄이 판정 상세(`/reviews/{id}/judgments/{jid}`) 링크로 나오고 "외 1건"이 붙는다

#### Scenario: 개정과 빈 작성 칸
- **WHEN** 문서를 더해 다시 판정했고 데이터시트 빈 작성 칸이 있는 검토의 요약을 부르면
- **THEN** 개정 줄 수 문장에 "바뀐 줄 보기"(`?rev=1`) 링크가, 빈 칸 문장에 "데이터시트 채우기" 링크가 있다

### Requirement: 홈 요약
시스템은 `GET /home/summary?user_id=`로 홈 요약을 돌려줘야 한다(SHALL). 첫 문장의 내 차례 검토 수는 홈 "내가 처리할 건"과 같은 규칙·같은 목록(최근 200건)으로 센다. 먼저 할 검토(마감 빠른 순)와 할 일, 상신 권장일·제출 마감, 분석이 멈춘 내 검토, 결재 중이거나 협조 회신을 기다리는 내 검토를 쓴다. 견적·품질·영업 사용자는 회신하지 않은 자기 부서 협조 요청 수를 쓴다. [결정 Q1]

#### Scenario: 내 차례 수가 홈 칸과 같음
- **WHEN** 엔지니어가 판정 확인 단계 검토 2건과 실패한 검토 1건을 가진 채 홈 요약을 부르면
- **THEN** 첫 문장이 "내 차례인 검토는 3건입니다."로 시작하고 마감이 가장 빠른 검토가 링크로 나온다

#### Scenario: 부서 사용자
- **WHEN** 품질 담당이 회신하지 않은 품질 협조 요청이 있는 채 홈 요약을 부르면
- **THEN** 내 차례 검토가 없다는 문장과 회신하지 않은 품질 요청 수, 협조 요청 화면 링크가 나온다

### Requirement: 요약 상자
화면은 검토 상세 제목 줄 아래와 홈 나의 업무 아래에 요약 상자를 보여야 한다(SHALL). 상자에는 "요약"과 "자동 요약" 꼬리표, 요약 시각, [다시 요약], 문장(링크는 그 화면으로 이동)이 있다. 요약을 부르지 못하면 상자를 숨기지 않고 "요약을 만들지 못했습니다"와 [다시 요약]을 보인다. 검토가 처리 중이면 검토 상세에는 상자를 두지 않는다. [결정 Q1]

#### Scenario: 검토 상세 요약 상자
- **WHEN** 담당자 확인 단계 검토 상세를 열면
- **THEN** 제목 줄 아래에 "요약" · "자동 요약" 상자와 꼭 볼 것 문장이 보이고, 일탈 후보 링크를 누르면 그 판정 상세로 간다

#### Scenario: 홈 요약 상자
- **WHEN** 엔지니어가 홈을 열면
- **THEN** 나의 업무 아래 요약 상자 첫 문장의 수가 "내가 처리할 건" 칸의 수와 같다

#### Scenario: 요약 실패
- **WHEN** 요약 API가 실패하면
- **THEN** 상자에 "요약을 만들지 못했습니다"가 보이고 [다시 요약]을 누르면 다시 부른다

### Requirement: 실행 기록의 흐름 기록
화면은 실행 기록 화면에서 줄을 펼치면 단계별 걸린 시간 아래에 흐름 기록(단계 이름, 걸린 시간, 바뀐 값, 사람 동작, 멈춘 자리)을 보여야 한다(SHALL). 흐름 기록이 없는 검토는 "흐름 기록 없음"을 보인다. 흐름 기록은 보기만 하고 바꾸는 단추는 없다. [제안 11-02, C2]

#### Scenario: 흐름 기록 펼치기
- **WHEN** 엔지니어가 실행 기록 화면에서 담당자 확인까지 처리한 검토 줄을 누르면
- **THEN** 흐름 기록에 판정 단계의 "판정 0 → n"과 "담당자 확인에서 멈춤"이 보인다

### Requirement: 이력 탭의 단계부터 다시 처리
화면은 검토 상세 "이력" 탭 위에 엔지니어이고 담당자 확인 단계일 때만 처리 단계 고르기, 사유 칸, [다시 처리] 단추를 보여야 한다(SHALL). 사유가 비면 단추가 눌리지 않는다. 누르면 처리 중 화면으로 바뀌고 끝나면 검토 상세로 돌아온다. 사람이 확정한 판정은 이어받는다는 안내를 함께 보인다. [제안 11-02, C2]

#### Scenario: 이력 탭에서 다시 처리
- **WHEN** 엔지니어가 담당자 확인 단계 검토의 이력 탭에서 "제품 비교 판정"을 고르고 사유를 적어 [다시 처리]를 누르면
- **THEN** 처리가 끝난 뒤 검토 상세가 다시 보이고 이력에 "제품 비교 판정부터 다시 처리"와 사유가 보인다

### Requirement: PDF 올리기
화면은 검토 등록과 문서 추가에서 docx와 함께 PDF 파일도 고를 수 있어야 하고, 서버에 둔 RFP 목록에 PDF도 보여야 한다(SHALL). docx·PDF가 아닌 파일은 거절 안내를 보인다. [제안 11-02]

#### Scenario: PDF로 검토 등록
- **WHEN** 엔지니어가 검토 등록에서 글자가 든 PDF 사양서를 올리고 분석을 시작하면
- **THEN** 분류 추천에 그 PDF가 보이고, 분석이 끝나 담당자 확인 단계가 된다

### Requirement: 검토 상세 탭 쪽 나누기
화면은 검토 상세의 위험 조건, 문서 읽기 점검, 상업 조건(비용 조건 표와 상업 영향 표 따로), 이력 탭의 목록이 10줄보다 많으면 한 쪽에 10줄(10·20·50줄 중 고름)씩 보이고 아래에 쪽 번호 줄을 두어야 한다(SHALL). 10줄 이하면 쪽 번호 줄을 두지 않는다. 탭 머리 숫자는 지금 쪽이 아니라 목록 전체로 센다. 상업 조건 탭에서 조항 종류를 바꾸면 1쪽으로 돌아간다.

#### Scenario: 상세 탭 쪽 나누기
- **WHEN** 문서 읽기 점검이 15건인 검토 상세의 문서 읽기 점검 탭을 열면
- **THEN** 점검 줄 10개와 "1–10 / 전체 15건" 쪽 번호 줄이 보이고 머리에는 "확인 안 함 15건"이 보이며, 2쪽을 누르면 점검 줄 5개가 보인다

#### Scenario: 짧은 목록은 쪽 번호 없음
- **WHEN** 이력이 10줄 이하인 검토 상세의 이력 탭을 열면
- **THEN** 이력 줄이 모두 보이고 쪽 번호 줄은 없다

### Requirement: 위험 조건 처리 알림
화면은 위험 조건 탭에서 위험으로 확정, 문제 없음으로 닫기, 위험 표현 사전에 추가 제안이 성공하면 공통 알림으로 그 표현(값 불일치는 항목 이름)과 바뀌는 것을 한 문장으로 보여야 한다(SHALL). 확정은 질의 후보와 결재 확인 사유에 남는다는 것, 닫기는 그 조건에서 만든 질의 후보가 목록에서 빠진다는 것, 사전 추가 제안은 규칙 담당이 판정 규칙 화면에서 반영하면 다음 검토부터 잡힌다는 것과 판정 규칙 화면 링크를 보인다. 실패는 알림 대신 그 자리 오류 문장으로 보인다.

#### Scenario: 위험으로 확정 알림
- **WHEN** 엔지니어가 “deemed” 후보 줄의 "위험으로 확정"을 누르면
- **THEN** 알림에 "“deemed”: 위험으로 확정했습니다"와 질의 후보·결재 확인 사유에 남는다는 문장이 보이고 그 줄은 확정 상태가 된다

#### Scenario: 문제 없음 알림
- **WHEN** 엔지니어가 “deemed” 후보 줄에서 "문제 없음"을 누르고 사유를 넣어 "닫기"를 누르면
- **THEN** 알림에 "“deemed”: 문제 없음으로 닫았습니다"와 질의 후보가 목록에서 빠진다는 문장이 보이고 그 줄은 문제 없음 상태가 된다

#### Scenario: 사전 추가 제안 알림
- **WHEN** 엔지니어가 놓친 표현을 넣고 "위험 표현 사전에 추가 제안"을 누르면
- **THEN** 알림에 그 표현의 사전 추가를 제안했다는 문장과 "판정 규칙 보기" 링크가 보이고 제안 목록에 그 표현이 보인다

### Requirement: 사전 추가 후보에서 제안 칸으로
화면은 위험 조건 탭 사전 추가 후보의 [사전 추가 제안]을 누르면 제안 칸에 그 문장(100자까지, 더 길면 100자 안의 마지막 낱말 경계에서 자르고 "100자가 넘어 낱말 경계에서 줄였습니다."를 알림에 더함)과 메모를 채운 뒤, 제안 칸이 보이게 화면을 옮기고 표현 칸에 커서를 두어 채운 문장을 모두 선택해야 한다(SHALL). 채운 줄을 잠깐 강조하고, 동작 결과 알림으로 표현만 남기고 줄인 뒤 제안하라고 알린다. 단추를 눌러도 제안을 바로 보내지는 않는다.

#### Scenario: 사전 추가 제안 칸으로 옮김
- **WHEN** 후보가 많아 제안 칸이 화면 밖에 있는 검토에서 첫 후보의 [사전 추가 제안]을 누르면
- **THEN** 제안 칸이 화면 안에 보이고 표현 칸에 커서가 있으며, 칸에 그 문장이 채워지고 "제안 칸에 문장을 채웠습니다" 알림이 보이고, 제안 목록은 그대로다

#### Scenario: 긴 문장은 낱말 경계에서 자름
- **WHEN** 100자보다 긴 후보 문장의 [사전 추가 제안]을 누르면
- **THEN** 표현 칸에는 100자 이하이고 낱말 중간에서 끊기지 않은 앞부분이 채워지고, 알림에 "낱말 경계에서 줄였습니다"가 보인다

### Requirement: 검토 목록 내가 처리할 건
화면은 검토 목록 요약 줄의 "내가 처리할 건"을 홈 나의 업무 "내가 처리할 건"과 같은 규칙·같은 목록으로 세야 한다(SHALL): 엔지니어는 자기가 담당인 검토 중 담당자 확인·반려됨·분석 실패인 것과 자기가 결재자인 결재 대기, 승인자는 자기가 결재자인(결재자가 없으면 모든) 결재 대기다. 담당 범위·기간·찾기 거름과 상관없이 같은 수이고, 마우스를 올리면 무엇을 세는지 보인다.

#### Scenario: 목록 내가 처리할 건은 홈과 같은 수
- **WHEN** 엔지니어에게 담당자 확인 검토 1건과 반려된 검토 1건이 있는 상태로 홈과 검토 목록을 열면
- **THEN** 두 화면의 "내가 처리할 건"이 같은 수 2이고, 검토 목록에서 담당 범위를 "팀 전체"로 바꿔도 2다

### Requirement: 실행 기록의 AI 사용량
화면은 실행 기록 화면 위쪽에 "AI 사용량" 상자를 보여야 한다(SHALL): 기간(7일·30일·90일, 기본 30일), 호출 합과 추정 비용 합(팀 가정 꼬리표, 모르면 "단가 모름"), 날짜·기능·모델·호출·토큰(입력/출력/생각)·추정 비용 표(날짜 최신순)와 기능 칩 거르기, 실제 청구 금액은 Google 결제 화면에서 확인한다는 안내. 기록이 없으면 중립색으로 "이 기간에 AI를 쓴 기록이 없습니다"를 보인다. 기능 이름은 응답 그대로 쓰고 합계는 응답 값을 쓴다. [제안 11-03]

#### Scenario: AI 사용량 보기
- **WHEN** 지난 30일에 분석과 검토 도우미 사용 기록이 있는 상태로 실행 기록 화면을 열면
- **THEN** AI 사용량 상자에 30일이 골라져 있고 호출 합과 추정 비용 합이 "팀 가정"과 함께 보이며, 표에 두 기능 줄이 날짜 최신순으로 보이고 Google 결제 화면 안내가 보인다

#### Scenario: 기간 바꾸기
- **WHEN** AI 사용량 상자에서 7일을 고르면
- **THEN** 7일 기간으로 다시 불러와 그 기간의 줄과 합계가 보인다

#### Scenario: 기능으로 거르기
- **WHEN** AI 사용량 상자에서 "검토 도우미" 칩을 누르면
- **THEN** 표에 검토 도우미 줄만 남고 그 칩이 눌린 상태로 보인다

#### Scenario: AI 사용 기록 없음
- **WHEN** 고른 기간에 AI 사용 기록이 없으면
- **THEN** 중립색으로 "이 기간에 AI를 쓴 기록이 없습니다"가 보이고 호출 0회가 보인다

#### Scenario: 단가 모름
- **WHEN** 사용량 합계의 추정 비용이 없으면
- **THEN** 비용 자리에 "단가 모름"이 보인다

### Requirement: 인계 패키지 만드는 동안 진행 표시
화면은 [인계 패키지 내려받기]를 누른 뒤 파일을 받을 때까지 인계 패키지 상자 안에 진행 막대, 퍼센트, 지금 하는 일("일탈 목록·질의서 Word 만드는 중", "TBE 준수표 엑셀 만드는 중", "데이터시트 엑셀 만드는 중", "zip으로 묶는 중")과 어림한 진행이라는 안내를 보여야 한다(SHALL). 막대는 받기 전까지 90 %를 넘지 않고, 받으면 100 %가 된 뒤 내려받고 동작 결과 알림을 보인다. 실패하면 막대를 지우고 오류 문장을 보인다.

#### Scenario: 인계 패키지 만드는 동안 진행 표시
- **WHEN** 엔지니어가 승인된 검토의 제출본 탭에서 [인계 패키지 내려받기]를 누르고 서버가 늦게 답하면
- **THEN** 상자 안에 진행 막대와 "Word 만드는 중" 같은 지금 하는 일, 어림한 진행 안내가 보이고 퍼센트가 90 %를 넘지 않으며, 받으면 막대가 사라지고 "zip 를 내려받았습니다" 알림이 보인다

### Requirement: 인계 패키지 미리 보기
화면은 결재가 승인된 검토의 인계 패키지 상자(제출본 탭, 사업 상세 인계 패키지 창)에 [미리 보기]를 두고, 누르면 "영업 인계 패키지" 창을 열어야 한다(SHALL). 창은 검토 번호·이름·사업·제출 마감과 숫자 칸(준수, 일탈, 질의, 확인 필요, 팀 가정, 견적 조건), 결재자·승인 시각, 금액은 비워 두었다는 안내, 탭 5개(표지: 설비 묶음별 수, TBE 준수표, 일탈·질의, 견적 조건, 영업 할 일)와 건수, [인계 패키지 내려받기]를 보인다. 숫자는 제출본(v1) 기준 응답 값이고 보기만 한다. [제안 11-03]

#### Scenario: 인계 패키지 미리 보기
- **WHEN** 엔지니어가 승인된 검토의 제출본 탭에서 [미리 보기]를 누르면
- **THEN** "영업 인계 패키지" 창이 열리고 검토 번호, 숫자 칸 준수·일탈·질의·확인 필요·팀 가정·견적 조건, 결재자, "금액은 비워 두었습니다" 안내, 표지 탭의 설비 묶음 카드가 보인다

#### Scenario: 미리 보기 탭 바꾸기
- **WHEN** 미리 보기 창에서 "TBE 준수표" 탭을 누르면
- **THEN** TBE 준수표 줄이 보이고 탭 옆 건수가 TBE 줄 수와 같다

#### Scenario: 사업 상세에서 미리 보기
- **WHEN** 사업 상세의 "인계 패키지 보기" 창에서 승인된 검토의 [미리 보기]를 누르면
- **THEN** 그 검토의 "영업 인계 패키지" 창이 열린다

### Requirement: 검토 목록 요약 줄 결재 완료·분석 중
화면은 검토 목록 요약 줄의 할 일 칸(내가 처리할 건, 결재 대기, 분석 실패) 뒤에 구분해 중립색으로 "결재 완료 n"(결재가 승인된 검토)과 "분석 중 n"(처리 중인 검토, 0이면 숨김)을 보여야 한다(SHALL). 두 칸은 결재 대기와 같은 범위(담당 범위·기간)로 세고, 마우스를 올리면 무엇을 세는지 보인다.

#### Scenario: 요약 줄 결재 완료·분석 중
- **WHEN** 내 검토가 담당자 확인 2건, 결재 대기 1건, 결재 완료 2건, 처리 중 1건인 상태로 검토 목록을 열면
- **THEN** 요약 줄에 "내가 처리할 건 2", "결재 대기 1", "결재 완료 2", "분석 중 1"이 보이고 칸 합이 "검토 6"과 같다

### Requirement: 요약 줄 칸으로 거르기
화면은 검토 목록 요약 줄의 칸(내가 처리할 건, 결재 대기, 분석 실패, 결재 완료, 분석 중)을 누르면 아래 목록을 그 칸에서 센 검토만으로 거르고, 거른 조건을 화면 주소에 남겨야 한다(SHALL). 거르는 동안 누른 칸은 눌린 상태로, 목록 위에 "<칸 이름> n건만 보는 중"과 [모두 보기]를 보인다. 같은 칸을 다시 누르거나 [모두 보기]를 누르거나 브라우저 뒤로 가기를 누르면 전체 목록으로 돌아온다. 칸 숫자와 거른 목록 수는 같은 규칙으로 센다.

#### Scenario: 검토 목록 요약 칸으로 거르기
- **WHEN** 결재 완료 검토가 2건인 상태로 검토 목록에서 "결재 완료" 칸을 누르면
- **THEN** 목록에 결재 완료 검토 2건만 남고 "결재 완료 2건만 보는 중"과 [모두 보기]가 보이며 칸이 눌린 상태이고, 같은 칸을 다시 누르면 모든 검토가 다시 보인다

#### Scenario: 뒤로 가기로 전체 목록
- **WHEN** 검토 목록에서 "내가 처리할 건" 칸을 눌러 거른 뒤 브라우저 뒤로 가기를 누르면
- **THEN** 거름이 풀려 모든 검토가 보이고 "…건만 보는 중" 띠가 없다

#### Scenario: 결재 대기 칸으로 거르기
- **WHEN** 결재 대기 검토가 2개 있는 상태에서 요약 줄의 "결재 대기" 칸을 누르면
- **THEN** 목록에 결재 대기 검토 2개만 남고, [모두 보기]를 누르면 다시 모든 검토가 보인다

### Requirement: 검토 등록 진행 표시
화면은 검토 등록에서 [등록하고 분석 시작]을 누른 뒤 등록이 끝날 때까지 진행 막대와 설명을 보여야 한다(SHALL). 내 컴퓨터의 파일을 올리는 동안은 실제로 보낸 크기·전체 크기·퍼센트("파일 올리는 중 · 12.3 / 45.6 MB · 27 %")를, 다 올린 뒤나 서버에 둔 RFP를 고른 경우는 끝을 모르는 막대와 "문서를 확인하고 검토를 만드는 중…"을 보인다. 실패하면 막대를 지우고 오류 문장을 보인다.

#### Scenario: 검토 등록 진행 표시
- **WHEN** 엔지니어가 검토 등록 3단계에서 [등록하고 분석 시작]을 누르고 서버가 늦게 답하면
- **THEN** 진행 막대와 "파일 올리는 중" 또는 "검토를 만드는 중" 설명이 보이고, 등록이 끝나면 막대가 사라지고 등록 완료 화면이 보인다

### Requirement: 판정 탭 원문 말풍선
화면은 판정 탭 표를 오른쪽 패널 없이 전체 폭으로 보이고, 판정 줄에 마우스를 잠시 올리거나 키보드 초점이 가면 그 줄 가까이에 말풍선으로 원문 위치와 원문 문장(요구값 강조)을 보여야 한다(SHALL). 마우스를 떼거나 초점이 떠나면 사라지고, 말풍선에는 고치는 단추가 없다. 줄을 누르거나 초점에서 Enter를 누르면 판정 상세 화면을 연다. [제안 11-03]

#### Scenario: 줄에 마우스를 올려 원문 보기
- **WHEN** 엔지니어가 판정 탭에서 판정 줄에 마우스를 올리면
- **THEN** 오른쪽 패널 없이 그 줄의 원문 위치와 원문 문장이 말풍선으로 보이고, 마우스를 떼면 사라진다

#### Scenario: 키보드로 판정 상세 열기
- **WHEN** 판정 줄에 키보드 초점을 두고 Enter를 누르면
- **THEN** 그 판정의 판정 상세 화면이 열린다

### Requirement: 판정 상세 보증값 입력
화면은 판정 상세 화면에서 보증값 작성 판정에 후보 값이 없으면 담당자 확인 단계의 엔지니어에게 보증값과 근거 입력 칸을 보여야 하고(SHALL), 둘 다 넣어야 저장할 수 있으며 저장하면 이력에 남는다. "Comply"는 보증값으로 넣을 수 없다.

#### Scenario: 판정 상세에서 보증값 넣기
- **WHEN** 엔지니어가 후보 값이 없는 보증값 작성 판정의 판정 상세 화면에서 보증값과 근거를 넣고 [입력]을 누르면
- **THEN** 그 보증값이 보증값 칸에 보이고 이력에 남는다

### Requirement: 판정 상세 검산 확인
화면은 판정 상세 화면에서 공학 검산 대상 판정에 "검산 확인" 상자를 보여야 한다(SHALL). 상자는 단시간 전류(kA)·주파수·최대 순간 전류(kA)를 원문 검산 값으로 채우고, 사람이 값을 바꾸면 서버의 같은 검산 규칙으로 계산식과 결과를 보이며, [원문 값으로]로 되돌린다. "참고 계산 · 판정은 바뀌지 않습니다"를 보이고 기록하지 않는다. 단위는 kA만 받는다(CR-10).

#### Scenario: 판정 상세에서 검산 확인
- **WHEN** 엔지니어가 검산 위반(50 kA, 50 Hz, 100 kA)인 최대 순간 전류 판정의 판정 상세에서 최대 순간 전류를 125로 바꾸면
- **THEN** 상자에 "50 kA × 2.5 = 125 kA"와 "통과"가 보이고, [원문 값으로]를 누르면 100과 "위반"으로 돌아오며 판정은 그대로다

### Requirement: 정답지 탭 검토 고르기
화면은 정답지·채점 화면 정답지 탭의 검토 목록 위에 검색 칸(검토 번호·검토 이름), [모두 고르기]·[모두 해제], 고른 수 "검토 n건 고름"을 보여야 한다(SHALL). [모두 고르기]·[모두 해제]는 검색으로 보이는 검토에만 적용하고, 고른 수는 검색과 상관없이 채점에 들어갈 검토 수를 센다. [제안]

#### Scenario: 검토 골라 채점하기
- **WHEN** 사람이 확인한 판정이 있는 검토 3건이 처음에 모두 골라진 정답지 탭에서 [모두 해제]를 누르고 검토 번호로 1건을 찾아 [모두 고르기]를 누른 뒤 "지금 채점하기"를 누르면
- **THEN** [모두 해제] 뒤 "검토 0건 고름"이, 찾은 뒤에는 그 검토만 목록에 보이고 "검토 1건 고름"이 보이며, 채점 요청에는 그 검토 하나만 들어간다
